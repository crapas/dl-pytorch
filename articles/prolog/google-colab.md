## 1. 구글 코랩이란

**구글 코랩**(Google Colaboratory, 줄여서 Colab)은 구글이 제공하는 웹 서비스다. 브라우저에서 주피터 노트북을 열고 실행할 수 있다. 구글 계정만 있으면 무료로 사용할 수 있다.

딥러닝을 배우는 입장에서 코랩의 장점은 두 가지다.

- **설치할 것이 없다.** 파이썬도, 파이토치도 이미 준비되어 있다. 브라우저만 있으면 된다.
- **GPU를 무료로 사용할 수 있다.** 그래픽 카드가 없는 컴퓨터에서도 GPU로 학습할 수 있다.

이 책의 예제는 모두 CPU에서도 동작하지만, 8장부터는 학습 시간이 길어진다. 그래픽 카드가 없다면 **7장까지는 내 컴퓨터에서 진행하고 8장부터 코랩을 함께 사용하는 방식**이 편하다. 물론 처음부터 끝까지 코랩으로 진행해도 된다.

### 코랩의 한계

무료로 제공하는 서비스이므로 제약도 있다.

- **일정 시간 사용하지 않으면 연결이 끊긴다.** 끊기면 내려받은 파일과 학습한 결과가 사라진다.
- **연속 사용 시간에 제한이 있다.** 오래 학습을 돌리면 중간에 끊길 수 있다.
- **GPU를 늘 배정받는 것은 아니다.** 사용량이 많은 시간대에는 기다려야 할 수 있다.

이 문서의 6절에서 끊겼을 때 무엇이 사라지고 어떻게 대비하는지 다룬다.

## 2. 코랩 사용법

### 노트북 열기

[colab.research.google.com](https://colab.research.google.com)에 접속해 구글 계정으로 로그인한다. 이 책의 노트북을 여는 방법은 3절에서 다루고, 여기서는 화면의 구성만 익혀 두자.

### 화면 구성

| 영역 | 설명 |
|---|---|
| 셀 | 코드나 설명이 들어가는 칸. 코드 셀과 텍스트 셀이 있다 |
| 왼쪽 세로 막대 | 목차, 파일 탐색기, 보안 비밀 등 |
| 오른쪽 위 | 연결 상태와 사용 중인 자원 표시 |
| 메뉴 | 파일, 수정, 보기, 삽입, 런타임, 도구 |

### 셀 실행

| 하고 싶은 일 | 방법 |
|---|---|
| 셀 하나 실행 | `Shift + Enter` 또는 셀 왼쪽의 실행 단추 |
| 실행하고 아래 셀 추가 | `Alt + Enter` |
| 전체 실행 | 런타임 → 모두 실행 |
| 실행 중단 | 런타임 → 실행 중단 |

**셀은 위에서 아래로 차례대로 실행한다.** 앞의 셀에서 만든 변수를 뒤의 셀이 사용하므로 순서를 건너뛰면 오류가 난다.

### 런타임이란

**런타임**(runtime)은 코랩이 내 노트북을 실행하려고 빌려주는 컴퓨터다. 노트북을 열면 구글의 서버 한 대가 배정되고, 그 위에서 코드가 돌아간다.

연결이 끊기면 이 컴퓨터를 반납하는 셈이라, 거기에 저장한 것도 함께 사라진다.

| 메뉴 | 하는 일 |
|---|---|
| 런타임 → 런타임 연결 해제 | 지금 쓰는 컴퓨터를 반납한다 |
| 런타임 → 세션 다시 시작 | 파이썬만 다시 시작한다. 파일은 남는다 |
| 런타임 → 런타임 유형 변경 | CPU, GPU, TPU 중에서 고른다 |

### 런타임 유형 고르기

**메뉴 → 런타임 → 런타임 유형 변경 → 하드웨어 가속기**에서 고른다.

| 선택 | 권장 여부 | 설명 |
|---|---|---|
| **GPU** | **권장** | 무료로 사용할 수 있다. 8장 이후는 CPU로도 동작하지만 매우 느려 사실상 필요하다 |
| CPU | 7장까지는 가능 | 느리지만 동작한다 |
| **TPU** | **고르지 말 것** | 아래 설명을 보자 |

> **TPU를 고르면 안 되는 이유.** TPU는 구글이 만든 딥러닝 전용 칩이다. 이름만 보면 GPU보다 좋아 보이지만, **이 책의 코드와는 맞지 않는다.**
>
> 이 책의 학습 코드는 일반적인 파이토치 방식으로 쓰여 있다. 반면 TPU는 연산을 모아 두었다가 한꺼번에 실행하는 방식이라 TPU 전용 코드가 따로 필요하다. 그래서 TPU 런타임에서 이 책의 노트북을 돌리면 **오류 없이 극도로 느려지거나 멈춘 것처럼 보인다.** 오류가 나지 않기 때문에 원인을 찾기가 더 어렵다.
>
> GPU를 배정받지 못했다면 TPU 대신 **CPU로 두고 기다리는 편**이 낫다.

## 3. 깃허브 예제 노트북 불러와 실행하기

### 노트북 열기

코랩에서 **파일 → 노트북 열기**를 고르고 **GitHub** 탭을 누른다. 입력창에 저장소 주소를 입력한다.

```
crapas/dl-pytorch
```

저장소의 노트북 목록이 나온다. 실습할 노트북을 고르면 코랩에서 바로 열린다.

### 그냥 실행하면 첫 셀부터 실패한다

**여기서 한 가지를 반드시 알아야 한다.** 노트북을 열고 그대로 실행하면 첫 셀에서 이런 오류가 난다.

```
ModuleNotFoundError: No module named 'code_reference'
```

이유는 이렇다. 이 책의 모든 노트북은 첫 셀에서 공통 라이브러리를 불러온다.

```python
import sys
sys.path.append('../../')

from code_reference import common
from code_reference import visualize as viz
```

`../../`는 **노트북 파일이 있는 폴더를 기준으로 두 단계 위**, 곧 저장소 최상위를 가리킨다. 내 컴퓨터에서 VS Code로 열면 기준 위치가 노트북이 있는 폴더(`code_examples/ch05/`)이므로 이 경로가 정확히 맞는다.

**코랩은 다르다. 노트북을 어디서 열든 기준 위치가 항상 `/content`다.**

| | 기준 위치 | `../../`가 가리키는 곳 |
|---|---|---|
| 내 컴퓨터 | `…/dl-pytorch/code_examples/ch05` | `…/dl-pytorch` (맞음) |
| **코랩** | **`/content`** | **`/`** (틀림) |

데이터 파일을 읽는 코드에서도 같은 문제가 생긴다.

```
FileNotFoundError: [Errno 2] No such file or directory: '../../data/ch3_spiral_data.csv'
```

구글 드라이브에 노트북을 올려 두어도 마찬가지다. 드라이브의 노트북을 코랩에서 열어도 기준 위치는 여전히 `/content`다.

### 해결 — 부트스트랩 셀

해결은 간단하다. **저장소를 통째로 받아 놓고, 노트북이 있는 폴더로 이동하면 된다.**

**노트북의 맨 첫 셀에 다음 코드를 넣는다.**

```python
# === 코랩 준비 (내 컴퓨터에서는 아무 일도 하지 않는다) ===
import os
import sys

if 'google.colab' in sys.modules:
    CHAPTER = 'ch05'                      # 실습할 장으로 바꾼다
    if not os.path.exists('/content/dl-pytorch'):
        !git clone -q --depth 1 https://github.com/crapas/dl-pytorch.git /content/dl-pytorch
    %cd /content/dl-pytorch/code_examples/{CHAPTER}
```

셀을 추가하려면 노트북 맨 위에 마우스를 올렸을 때 나타나는 **`+ 코드`** 단추를 누른다.

**고칠 곳은 `CHAPTER` 한 줄뿐이다.** 연습 문제 노트북을 실행한다면 마지막 줄의 `code_examples`를 `exercises`로 바꾼다.

이 셀을 넣으면 그다음부터는 내 컴퓨터와 똑같이 동작한다. 노트북 본문의 `../../`도, 데이터 파일 경로도 손댈 필요가 없다.

| 환경 | 이 셀이 하는 일 |
|---|---|
| 내 컴퓨터 | `if` 안으로 들어가지 않는다. 아무 일도 하지 않는다 |
| 코랩 | 저장소를 `/content`에 받고 해당 장 폴더로 이동한다 |

> **왜 `/content`에 받는가.** 구글 드라이브에 받아 두고 싶을 수 있지만 권하지 않는다. 드라이브는 네트워크로 연결되는 저장소라, **작은 파일을 많이 읽고 쓸 때 매우 느리다.** 하루에 주고받을 수 있는 양에도 제한이 있다.
>
> 이 책의 예제는 그런 작업이 많다. MNIST나 CIFAR-10은 압축을 풀면 파일이 수천 개이고, 12장과 13장의 모델 파일은 수 GB다.
>
> `/content`는 코랩이 빌려준 컴퓨터의 디스크라 빠르다. **저장소와 데이터는 `/content`에 두고, 남기고 싶은 결과만 마지막에 드라이브로 복사하는 것**이 좋다(7절).

### 공통 라이브러리는 어떻게 되는가

부트스트랩 셀이 저장소를 통째로 받으므로 **공통 라이브러리(`code_reference`)도 함께 받아진다.** 따로 할 일이 없다.

노트북의 첫 셀에 있는 다음 코드가 그대로 동작한다.

```python
import sys
sys.path.append('../../')

from code_reference import common
from code_reference import visualize as viz
```

부트스트랩 셀이 `%cd`로 노트북이 있는 폴더로 이동해 두었기 때문에, `../../`가 저장소 최상위를 정확히 가리킨다. 공통 라이브러리의 사용법은 내 컴퓨터에서와 완전히 같다. 자세한 것은 [프롤로그 3-1](README.md#3-1-공통-라이브러리)을 보자.

### 첫 실행에서 만나는 한글 글꼴 안내

그래프에 한글을 사용하려면 한글 글꼴이 필요한데, 코랩에는 기본으로 설치되어 있지 않다. 공통 라이브러리가 자동으로 설치를 시도하지만, **설치한 글꼴은 지금 실행 중인 세션에 바로 반영되지 않는다.**

그래서 첫 실행에서 이런 메시지를 만난다.

```
FileNotFoundError: 나눔 고딕 폰트를 설치했습니다. 노트북 커널을 다시 시작한 후 다시 시도하세요.
```

**오류가 아니라 안내다.** 시키는 대로 하면 된다.

1. **런타임 → 세션 다시 시작**
2. 첫 셀부터 다시 실행

다시 시작해도 `/content`에 받아 둔 저장소는 남아 있으므로, 부트스트랩 셀은 내려받기를 건너뛰고 폴더 이동만 한다. **두 번째 실행부터는 이 일이 없다.**

## 4. 서드파티 라이브러리 설치하기

### 코랩에 이미 있는 것

코랩에는 파이토치, torchvision, numpy, matplotlib가 이미 설치되어 있다. **1장부터 11장까지도 일부 노트북은 별도 라이브러리가 필요하다.** `torchinfo`(2-3절~8-3절의 여러 노트북), `scikit-learn`(4-2절), `timm`·`kagglehub`(8-4절)이 그 예다. 코랩에 없는 것은 각 노트북의 '실습 준비'를 보고 설치한다.

버전을 확인하려면 이렇게 한다.

```python
import torch
print(torch.__version__)
```

### 설치하는 방법

코드 셀에서 `!pip install`로 설치한다. 앞의 느낌표는 "이것은 파이썬 코드가 아니라 명령이다"라는 뜻이다.

```python
!pip install -q transformers
```

`-q`는 설치 과정의 출력을 줄여 화면을 깔끔하게 해 준다.

### 어떤 절에서 무엇이 필요한가

각 노트북의 첫 부분에 **'실습 준비'** 라는 항목을 두어 그 절에서 필요한 라이브러리를 적어 두었다. 그것을 보고 설치하면 된다.

12장과 13장에서 주로 필요하다.

```python
# 12-1, 12-2, 13장
!pip install -q transformers datasets accelerate

# 12-3 (양자화)
!pip install -q transformers accelerate bitsandbytes
# QLoRA 심화 자료(articles/qlora)까지 실행하려면 peft도 함께 설치: !pip install -q peft

# 12-4 (검색 증강 생성)
!pip install -q transformers sentence-transformers groq
```

### 설치할 때 주의할 점

**버전을 지정할 때는 따옴표로 감싸자.**

```python
!pip install -q 'accelerate>=1.1.0'      # 올바른 방법
!pip install -q accelerate>=1.1.0        # 잘못된 방법
```

따옴표가 없으면 `>` 기호를 '출력을 파일로 보내라'는 뜻으로 해석한다. 버전 조건은 무시되고 `=1.1.0`이라는 이상한 이름의 빈 파일이 만들어진다.

**설치 후 세션 재시작을 요구하는 경우가 있다.** 코랩이 안내 단추를 보여 주면 눌러서 재시작하고, 첫 셀부터 다시 실행한다. 이미 설치된 라이브러리의 버전이 바뀌었을 때 생기는 일이다.

**설치한 라이브러리는 세션이 끊기면 사라진다.** 다시 연결하면 설치 셀을 다시 실행해야 한다.

### 8-4절 — 캐글 데이터셋

흉부 X선 데이터셋은 `kagglehub`로 캐글에서 받는다. 약 2.3GB이므로 디스크 여유를 확인하자. 인증을 요구하면 캐글 계정에서 API 토큰을 발급받아 설정한다.

### 12-4절 — API 키

본문 예제는 외부의 언어 모델 서비스를 사용한다. 해당 서비스에서 무료 계정을 만들고 키를 발급받아야 한다.

코랩에서는 키를 코드에 직접 적지 말고 **왼쪽 세로 막대의 열쇠 모양 아이콘(보안 비밀)** 에 저장하는 편이 안전하다. 노트북을 공유했을 때 키가 함께 나가는 사고를 막을 수 있다.

```python
from google.colab import userdata
os.environ['GROQ_API_KEY'] = userdata.get('GROQ_API_KEY')
```

키 없이도 실습할 수 있도록 예제 노트북에 **작은 모델을 내려받아 대신 사용하는 분기**를 넣어 두었다.

### 13-2절 — 큰 모델

13-2절의 모델은 10GB가 넘는다. 코랩의 디스크로도 받을 수 있지만 **시간이 꽤 걸린다.** 받는 도중 세션이 끊기면 처음부터 다시 받아야 하므로, 시간 여유가 있을 때 실행하자.

## 6. 세션이 끊기면 무엇이 사라지는가

코랩 세션은 **일정 시간 사용하지 않으면 끊긴다.** 끊기면 빌려 쓰던 컴퓨터를 반납하는 것이므로 `/content` 아래가 모두 지워진다.

| 사라지는 것 | 대응 |
|---|---|
| `/content/dl-pytorch` (저장소) | 부트스트랩 셀이 다시 받는다. 신경 쓸 것 없다 |
| 설치한 라이브러리 | 설치 셀을 다시 실행한다 |
| 내려받은 데이터셋과 모델 | 다시 받아야 한다. 13-2절처럼 큰 모델은 시간이 든다 |
| **학습한 모델 파라미터** | **미리 저장해 두지 않으면 잃는다** |
| 노트북의 코드 | 구글 드라이브에 저장되므로 남는다 |

**긴 학습을 돌릴 때는 브라우저 탭을 열어 두자.** 탭을 닫으면 사용하지 않는 것으로 판정되어 더 빨리 끊긴다.

## 8. 자주 만나는 문제

| 증상 | 원인과 해결 |
|---|---|
| `ModuleNotFoundError: No module named 'code_reference'` | 부트스트랩 셀이 없거나 실행되지 않았다. 3절의 셀을 첫 셀로 넣고 처음부터 실행 |
| `FileNotFoundError: '../../data/...'` | 같은 원인 |
| `FileNotFoundError: 나눔 고딕 폰트를 설치했습니다…` | 글꼴 설치 직후다. **세션 다시 시작** 후 처음부터 실행(3절) |
| 그래프의 한글이 네모로 보인다 | 같은 원인 |
| 학습이 오류 없이 멈춘 듯 느리다 | **TPU 런타임**을 골랐다. GPU 또는 CPU로 변경(2절) |
| `CUDA out of memory` | 이전 모델이 메모리에 남아 있다. `del model` 후 `torch.cuda.empty_cache()`, 안 되면 세션 다시 시작 |
| 양자화 실행이 지나치게 느림 | CPU 런타임에서 12-3절을 실행했다. **GPU 런타임**으로 변경 |
| `=1.1.0`이라는 이상한 파일이 생겼다 | 버전 조건을 따옴표로 감싸지 않았다(4절) |
| 디스크가 부족하다 | 큰 모델을 여러 개 받았다. 세션 다시 시작으로 `/content`를 비운다 |
| 설치한 라이브러리를 찾을 수 없다 | 세션이 끊겼다 다시 연결되었다. 설치 셀을 다시 실행 |

## 9. 요약

**처음 시작할 때 이 순서로 하면 된다.**

1. 코랩에서 **파일 → 노트북 열기 → GitHub** 탭에 `crapas/dl-pytorch`를 입력해 노트북을 연다
2. **런타임 → 런타임 유형 변경 → GPU**를 고른다. TPU는 고르지 않는다
3. 맨 위에 셀을 하나 추가하고 **3절의 부트스트랩 셀**을 붙여 넣는다. `CHAPTER`만 바꾼다
4. 12장과 13장이라면 필요한 라이브러리를 설치한다(4절)
5. 위에서부터 차례대로 실행한다
6. 글꼴 안내가 나오면 **세션 다시 시작** 후 처음부터 다시 실행한다
7. 남기고 싶은 결과는 **드라이브로 복사한다**(7절)

**한 가지만 기억하면 된다.** 코랩의 기준 위치는 언제나 `/content`이므로, **저장소를 받아 놓고 노트북이 있는 폴더로 들어가는 일**만 해 주면 나머지는 내 컴퓨터와 똑같이 동작한다.
