## 1. WSL이란

**WSL**(Windows Subsystem for Linux)은 윈도우 안에서 리눅스를 실행할 수 있게 해 주는 기능이다. 윈도우를 지우거나 컴퓨터를 다시 시작하지 않고도, 시작 메뉴에서 프로그램 하나를 실행하듯 리눅스 터미널을 열 수 있다.

**WSL2**는 WSL의 현재 지원 버전을 말하며, 따로 밝히지 않은 경우에도 WSL은 WSL2를 말한다. 윈도우 안에서 진짜 리눅스 커널을 가볍게 돌리는 방식이라 GUI 앱을 포함한 리눅스용 프로그램이 거의 그대로 동작한다.

### 왜 WSL2를 고려하는가

윈도우에 직접 설치해도 이 책의 예제는 모두 돌아간다. 그런데도 WSL2를 권하는 이유가 있다.

- **딥러닝 생태계의 기준이 리눅스이다.** 논문 저자가 공개한 코드, 깃허브의 설치 안내, 오류를 검색했을 때 나오는 해결책이 대부분 리눅스 기준으로 쓰여 있다. 리눅스 환경이면 그대로 따라 할 수 있다.
- **윈도우에서만 생기는 문제를 피할 수 있다.** 경로 길이 제한, 일부 라이브러리의 윈도우 지원 문제 같은 것들이다. 12-3절에서 사용하는 양자화 라이브러리가 대표적이다.
- **나중에 실무에서 접하게 될 환경도 대부분 리눅스를 기반으로 한다.** 딥러닝 학습을 돌리는 서버는 대부분 리눅스다.

단계가 하나 늘고, 윈도우와 리눅스 두 세계를 오가게 되므로 처음에는 조금 헷갈릴 수 있다. 이 문서는 헷갈리기 쉬운 지점을 그때그때 짚으며 진행한다.

## 2. WSL2와 우분투 설치

### 설치 요건

설치하기 전에 다음을 확인한다.

- **윈도우 버전.** 윈도우 11, 또는 윈도우 10 버전 2004(빌드 19041) 이상이어야 한다. 시작 메뉴 검색창에 `winver`를 입력하면 버전을 볼 수 있다. 홈과 프로 에디션 모두 사용할 수 있다.
- **가상화 기능.** WSL2는 가상화 기술을 사용하므로 컴퓨터에서 가상화가 켜져 있어야 한다. **작업 관리자 → 성능 → CPU**에서 '가상화'가 **사용**으로 표시되면 된다. '사용 안 함'이라면 컴퓨터를 켤 때 들어가는 BIOS(UEFI) 설정에서 가상화 항목(Intel VT-x, AMD-V, SVM 등 제조사마다 이름이 다르다)을 켜야 한다.
- **관리자 권한과 인터넷 연결.** 설치할 때 WSL 구성 요소와 우분투를 내려받는다. 회사나 학교에서 관리하는 컴퓨터는 정책으로 설치가 막혀 있을 수 있다.
- **저장 공간.** 우분투와 이후에 설치할 파이토치, 데이터셋을 담을 여유 공간이 필요하다. C 드라이브에 여유가 넉넉한지 확인한다.

### 1단계: WSL2 설치

WSL2와 우분투를 한 번에 설치하는 방법도 있지만, 이 문서는 **둘을 나누어 설치한다.** 문제가 생겼을 때 어느 쪽이 원인인지 바로 알 수 있기 때문이다.

시작 메뉴에서 **PowerShell**을 찾아 **관리자 권한으로 실행**한다. 아이콘을 오른쪽 클릭하면 '관리자 권한으로 실행' 항목이 나온다. 먼저 우분투 없이 WSL2만 설치한다.

```powershell
wsl --install --no-distribution
```

설치가 끝나면 **컴퓨터를 다시 시작한다.** 재시작한 뒤 PowerShell에서 다음 명령으로 설치를 확인한다.

```powershell
wsl --version
```

WSL 버전 정보가 출력되면 정상이다. 이미 WSL이 설치된 컴퓨터는 1단계를 건너뛰고 2단계로 가도 된다.

### 2단계: 우분투 설치

WSL2가 준비되었으니 리눅스 배포판인 우분투를 설치한다. 먼저 설치할 수 있는 배포판의 목록과 정확한 이름을 확인한 다음, **우분투 24.04**를 설치한다.

```powershell
wsl --list --online
wsl --install -d Ubuntu-24.04
```

이 책은 우분투 24.04를 기준으로 설명한다. 다른 배포판이나 버전을 사용해도 되지만, 패키지를 설치하는 명령이 조금씩 다를 수 있다.

다운로드가 끝나면 우분투 설정이 이어진다. 내려받는 데 시간이 조금 걸리니 기다린다.

### 첫 실행

설치가 끝나면 우분투 창이 저절로 열리거나, 시작 메뉴에서 **Ubuntu**를 실행하면 열린다. 처음 실행할 때 사용자 이름과 비밀번호를 정하라고 한다.

- **사용자 이름** 영문 소문자로 짧게 정한다. 윈도우 계정과 달라도 된다.
- **비밀번호** 입력해도 화면에 아무것도 보이지 않는다. 리눅스에서는 비밀번호를 입력할 때 글자 수조차 표시하지 않는다. 고장이 아니니 그대로 입력하고 엔터를 누른다.

이 비밀번호는 나중에 `sudo` 명령을 사용할 때 필요하다. `sudo`는 관리자 권한으로 명령을 실행하라는 뜻으로, 시스템에 프로그램을 설치할 때 사용한다.

### 패키지 목록 갱신

리눅스는 **패키지 관리자**로 프로그램을 설치한다. 우분투는 `apt`를 사용한다. 설치 가능한 프로그램의 목록을 먼저 갱신하고, 이미 설치된 것을 최신으로 올린다.

```bash
sudo apt update
sudo apt upgrade -y
```

처음 실행하면 비밀번호를 묻는다. 시간이 조금 걸린다.

### 두 세계를 구분하기

앞으로 명령을 입력할 창이 두 가지다. **지금 어느 쪽에 입력하는지 늘 확인하자.**

| | PowerShell (윈도우) | Ubuntu 터미널 (리눅스) |
|---|---|---|
| 프롬프트 | `PS C:\Users\...>` | `사용자@컴퓨터:~$` |
| 경로 표기 | `C:\dev\...` | `/home/사용자/...` |
| 패키지 설치 | 설치 프로그램을 내려받아 실행 | `sudo apt install ...` |

**이 문서에서 2절의 설치 명령을 빼면 거의 모두 Ubuntu 터미널에 입력한다.** 9절의 드라이버 설치만 예외다.

## 3. 파이썬 확인과 설치

우분투 24.04에는 파이썬 3.12가 기본으로 들어 있다. 이 책이 지원하는 범위(**3.12 이상 3.14 이하**) 안이므로 그대로 사용해도 된다.

```bash
python3 --version
```

가상 환경을 만들고 패키지를 설치하는 데 필요한 도구를 설치한다.

```bash
sudo apt install -y python3-venv python3-pip python3-dev git
```

각각 이런 역할을 한다.

| 패키지 | 역할 |
|---|---|
| `python3-venv` | 가상 환경을 만드는 도구 |
| `python3-pip` | 파이썬 패키지를 설치하는 도구 |
| `python3-dev` | 파이썬의 헤더 파일. 아래 설명 참고 |
| `git` | 예제 저장소를 내려받는 데 사용 |

> **`python3-dev`를 꼭 함께 설치하자.** 지금 당장은 필요 없어 보이지만, 최신 파이토치는 일부 연산을 실행하는 시점에 C 코드로 컴파일한다. 이때 이 패키지에 들어 있는 헤더 파일이 필요하다. 없으면 평범해 보이는 코드가 컴파일 오류로 멈추는 일이 생긴다. 컴파일에 필요한 도구도 함께 설치해 두자.
>
> ```bash
> sudo apt install -y build-essential
> ```

### 더 높은 버전의 파이썬을 사용하려면

기본 파이썬으로도 충분하지만 더 높은 버전을 사용하고 싶다면 **deadsnakes**를 추가한다. 우분투가 공식으로 제공하지 않는 파이썬 버전을 모아 둔 저장소다.

```bash
sudo add-apt-repository -y ppa:deadsnakes/ppa
sudo apt update
sudo apt install -y python3.14 python3.14-venv python3.14-dev
```

설치한 뒤에는 `python3` 대신 `python3.14`로 실행한다. **기본 파이썬을 바꾸지는 말자.** 우분투의 일부 시스템 도구가 기본 파이썬을 사용하므로 바꾸면 문제가 생길 수 있다.

## 4. VS Code와 확장 설치

**VS Code는 윈도우 쪽에 설치한다.** 리눅스 안에 설치하는 것이 아니다. [VS Code 내려받기 페이지](https://code.visualstudio.com/)에서 윈도우용을 받아 설치한다.

VS Code를 실행한 뒤 확장을 설치한다.

1. 왼쪽 세로 막대에서 **확장**(Extensions) 아이콘을 누른다. 네모 블록 네 개가 모인 모양이고, 단축키는 `Ctrl+Shift+X`다.
2. 검색창에 확장 이름을 입력하고, **마이크로소프트(Microsoft)가 배포한 것**을 골라 설치한다. 이름이 같은 확장이 여러 개 보일 수 있으므로 배포자를 확인한다.

설치할 확장은 다음과 같다.

| 확장 | 역할 |
|---|---|
| **WSL** | VS Code를 리눅스 쪽에 연결한다. **WSL2를 사용한다면 반드시 필요하다** |
| **Python** | 파이썬 문법 강조, 자동 완성, 가상 환경 인식 |
| **Jupyter** | 노트북 파일을 열고 셀을 실행 |

이 확장이 있어야 노트북 파일을 열고 셀을 실행할 수 있다. 메뉴를 한국어로 보고 싶다면 **Korean Language Pack**도 함께 설치한다.

> **WSL 확장이 하는 일.** 이것이 없으면 VS Code는 윈도우 쪽 파일만 다룬다. WSL 확장을 설치하면 VS Code가 리눅스 안의 파일을 직접 열고, 리눅스 안의 파이썬으로 코드를 실행한다. 화면은 윈도우에 보이지만 실제 작업은 리눅스에서 일어나는 구조다.

## 5. 예제 저장소 내려받기

### Git 확인

예제 저장소는 **Git**으로 받는다. Git은 소스 코드의 변경 이력을 관리하는 도구로, 저장소를 통째로 받고 나중에 갱신하는 데 사용한다.

**Ubuntu 터미널**에서 확인한다. 3절에서 `git`을 함께 설치했으므로 이미 준비되어 있을 것이다.

```bash
git --version
```

`git version 2.x.x`처럼 출력되면 된다. 명령을 찾을 수 없다면 설치한다.

```bash
sudo apt install -y git
```

> **윈도우 쪽에 Git을 따로 설치할 필요는 없다.** 저장소를 리눅스 파일 시스템 안에 두고 리눅스 쪽 Git으로 다루기 때문이다. 윈도우에 Git for Windows가 이미 설치되어 있어도 그것과는 별개로 동작한다.

### 내려받기

```bash
cd ~
git clone https://github.com/crapas/dl-pytorch.git
cd dl-pytorch
```

`~`는 리눅스에서 자신의 홈 폴더를 뜻한다. `/home/사용자` 위치다.

> **저장소를 반드시 리눅스 파일 시스템 안에 두자.** WSL에서는 `/mnt/c/` 아래로 윈도우의 C 드라이브에 접근할 수 있다. 하지만 거기에 저장소를 두면 파일을 읽고 쓸 때마다 윈도우와 리눅스 사이를 오가느라 **눈에 띄게 느려진다.** 데이터셋에서 작은 파일을 수천 개씩 읽는 학습에서는 차이가 크다. 홈 폴더(`~`) 아래에 두자.

나중에 예제를 갱신하려면 저장소 폴더에서 실행한다.

```bash
git pull
```

## 6. 가상 환경 만들기

### 가상 환경이란

파이썬 프로젝트마다 필요한 라이브러리와 버전이 다르다. 모든 라이브러리를 한곳에 설치하면 프로젝트끼리 버전이 충돌한다. **가상 환경**은 프로젝트마다 라이브러리를 담는 상자를 따로 두는 장치다. 이 책의 라이브러리를 이 책 전용 상자에 담아 두면 다른 프로젝트에 영향을 주지도 받지도 않는다.

최근 우분투에서는 가상 환경이 선택이 아니다. 시스템 파이썬에 `pip`로 패키지를 설치하려고 하면 `externally-managed-environment`라는 오류와 함께 막힌다. 시스템이 사용하는 파이썬을 보호하기 위한 장치다.

### 만들고 활성화하기

저장소 폴더(`~/dl-pytorch`)에서 실행한다.

```bash
python3 -m venv .venv
source .venv/bin/activate
```

3.14를 따로 설치했다면 첫 줄을 `python3.14 -m venv .venv`로 바꾼다.

성공하면 프롬프트 앞에 `(.venv)`가 붙는다.

```
(.venv) 사용자@컴퓨터:~/dl-pytorch$
```

**이후의 모든 명령은 이 상태에서 실행한다.**

### 가상 환경 사용법

| 하고 싶은 일 | 명령 |
|---|---|
| 활성화 | `source .venv/bin/activate` |
| 비활성화 | `deactivate` |
| 지금 활성화되어 있는지 확인 | 프롬프트 앞의 `(.venv)` 표시를 본다 |
| 통째로 지우기 | `deactivate` 후 `rm -rf .venv` |

**터미널을 새로 열 때마다 활성화해야 한다.** 활성화하지 않은 채로 설치하면 엉뚱한 곳에 들어가거나 위에서 말한 오류가 난다.

> 위의 예제에서 .venv는 가상환경의 이름인 동시에, 가상 환경 실행에 필요한 파일이 저장되는 디렉터리의 이름이다. 경우에 따라서는 같은 프로젝트에 서로 다른 조합의 라이브러리를 사용해야 할 때도 있다. 예를 들어 CUDA 적용 환경과 CUDA 비적용 환경을 함께 사용한다면, 같은 디렉터리에서 이름이 다른 두 개의 가상 환경을 만들어 사용하면 된다. .venv와 .venv_cuda 두 개의 가상 환경을 만든 경우, .venv에 설치된 라이브러리는 .venv_cuda에 영향을 주지 않으며, 사용할 수도 없고, 그 반대 방향도 성립한다. 

## 7. 파이토치와 라이브러리 설치

### NVIDIA 그래픽 카드가 없는 경우

**리눅스에서는 CPU 버전의 파이토치를 설치 경로를 지정해 따로 설치해야 한다.** 윈도우와 다른 점이다.

```bash
pip install -c requirements.txt torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

그냥 `pip install torch`라고 하면 CUDA가 포함된 설치본이 받아진다. 리눅스용 기본 설치본이 그렇게 되어 있기 때문이다. 그래픽 카드가 없다면 쓰지도 않을 라이브러리를 몇 GB씩 내려받게 되므로, **CPU용 경로를 지정해 저장 공간을 아낄 수 있다.**

`requirements.txt`는 저장소에 들어 있는 파일로, 필요한 라이브러리와 버전이 적혀 있다. `numpy`, `matplotlib`를 비롯해 [프롤로그](README.md)에서 소개한 것이 설치된다. 그래서 **저장소 폴더(`~/dl-pytorch`)에서 실행해야 한다.**

`--index-url` 뒤의 주소가 "어디서 받을지"를 지정하는 부분이고, 끝의 `cpu`가 CPU 전용이라는 뜻이다.

**`-c requirements.txt`를 빼먹지 말자.** `-c`는 설치할 것을 정하지 않고 **버전의 범위만 제한**하는 옵션이다. 이것이 없으면 CPU용 인덱스에서 가장 최신 버전의 파이토치가 설치된다. 그런데 `requirements.txt`는 `torch~=2.12.0`처럼 버전을 제한하고 있어서, 다음 명령이 방금 설치한 파이토치를 지우고 **PyPI의 기본 설치본(CUDA 포함)으로 바꿔 버린다.** 오류 없이 끝나기 때문에 알아차리기 어렵다. `-c requirements.txt`를 붙이면 두 명령이 같은 버전 조건을 따르므로 이런 일이 생기지 않는다.

### NVIDIA 그래픽 카드가 있는 경우

**9절을 먼저 읽자.** 설치 방법에 차이가 있다.

### 설치 확인

```bash
python -c "import torch; print(torch.__version__)"
```

`2.12.1+cpu`처럼 버전의 **끝이 `+cpu`로 출력되면** 성공이다. `+cpu`가 없이 `2.12.1`처럼 출력된다면 PyPI의 기본 설치본(CUDA 포함)이 설치된 것이다. 가상 환경을 지우고(`deactivate` 후 `rm -rf .venv`) 가상 환경 만들기부터 다시 하되, 파이토치 설치 명령에 `-c requirements.txt`를 빠뜨리지 않았는지 확인한다.

### pip 사용법

책을 진행하면서 절마다 추가 라이브러리를 설치하게 되므로 몇 가지만 알아 두자.

| 하고 싶은 일 | 명령 |
|---|---|
| 설치 | `pip install 패키지이름` |
| 여러 개 한 번에 | `pip install 패키지1 패키지2` |
| 파일에 적힌 목록대로 | `pip install -r requirements.txt` |
| 버전을 지정해 설치 | `pip install "패키지이름>=1.2"` |
| 설치된 목록 보기 | `pip list` |
| 삭제 | `pip uninstall 패키지이름` |

**버전을 지정할 때는 따옴표로 감싸자.** 따옴표가 없으면 `>` 기호를 터미널이 '출력을 파일로 보내라'는 뜻으로 해석해, 버전 조건은 무시되고 이상한 이름의 빈 파일이 만들어진다.

## 8. 한글 글꼴 설치와 노트북 실행

이 과정을 건너뛰면 첫 셀에서 글꼴을 찾을 수 없다는 안내를 만난다. **설치한 뒤에는 노트북 커널을 다시 시작해야 반영된다.**

cd ~/dl-pytorch

처음 실행하면 VS Code가 리눅스 쪽에 필요한 구성 요소를 설치하느라 조금 기다린다. 잠시 후 VS Code 창이 열리는데, **왼쪽 아래 모서리에 `WSL: Ubuntu-24.04`라고 표시되면 제대로 연결된 것이다.**

### 노트북 실행

**2번이 가장 중요하다.** 커널은 노트북의 코드를 실제로 실행하는 파이썬을 가리킨다. 여기서 윈도우 쪽 파이썬이 아니라 **리눅스 안의 `.venv`** 를 골라야 한다. WSL 확장이 제대로 연결되어 있으면 목록에 리눅스 쪽 경로(`~/dl-pytorch/.venv/bin/python`)가 표시된다.

## 9. NVIDIA 그래픽 카드 사용하기

> 그래픽 카드가 없거나 사용하지 않을 생각이라면 이 절을 건너뛰어도 된다.

### CUDA란

**CUDA**는 NVIDIA가 만든 기술로, 그래픽 카드로 일반적인 계산을 수행할 수 있게 해 준다. 딥러닝의 학습은 같은 계산을 엄청나게 많이 되풀이하는 작업이라 CPU보다 그래픽 카드가 훨씬 빠르다. 모델에 따라 수십 배 차이가 난다.

WSL2에서도 CUDA를 그대로 사용할 수 있다.

### 드라이버는 윈도우 쪽에만 설치한다

**여기가 가장 헷갈리는 대목이다.** 반드시 지키자.

| | 할 일 |
|---|---|
| **윈도우** | NVIDIA 그래픽 드라이버를 설치한다 |
| **WSL 안(리눅스)** | 드라이버를 설치하지 **않는다** |

리눅스 안에서 리눅스용 드라이버를 설치하면 오히려 연결이 망가진다. 인터넷에서 리눅스 CUDA 설치 안내를 보고 그대로 따라 하다 생기는 흔한 문제다.

윈도우 쪽 드라이버는 [NVIDIA 드라이버 페이지](https://www.nvidia.com/Download/index.aspx)에서 받는다. 대부분의 컴퓨터에는 이미 설치되어 있다.

### 확인

**Ubuntu 터미널에서** 실행한다.

```bash
nvidia-smi
```

표가 출력되면 준비된 것이다. 윈도우 쪽 드라이버가 리눅스 안까지 연결된 상태다. **표 오른쪽 위의 `CUDA Version:` 값을 적어 두자.**

이 값은 "이 드라이버가 지원하는 CUDA의 최대 버전"을 뜻한다. CUDA가 설치되어 있다는 뜻이 아니다.

> **CUDA 툴킷을 따로 설치할 필요는 없다.** 인터넷에 'CUDA 툴킷을 설치하라'는 안내가 많지만, 파이토치를 사용할 목적이라면 필요하지 않다. 필요한 CUDA 라이브러리가 파이토치 설치본 안에 들어 있다.

### 파이토치 설치

파이토치는 CUDA 버전별로 설치본을 따로 제공한다. **드라이버가 지원하는 CUDA 버전보다 높은 것을 설치하면 동작하지 않으므로**, 앞에서 확인한 값보다 같거나 낮은 것을 고른다.

설치 명령은 [파이토치 공식 설치 안내 페이지](https://pytorch.org/get-started/locally/)에서 자신의 환경을 고르면 그 자리에서 만들어 준다. 운영체제는 **Linux**를 고른다. WSL2는 리눅스이기 때문이다.

명령의 모양은 이렇다.

```bash
pip install --upgrade -c requirements.txt torch torchvision --index-url https://download.pytorch.org/whl/cu132
pip install -r requirements.txt
```

끝의 `cu132`가 CUDA 13.2용이라는 뜻이고, 이 숫자가 버전에 따라 달라진다. 저장소 폴더(`~/dl-pytorch`)에서 실행한다.

**`-c requirements.txt`를 빼먹지 말자.** 7절에서 설명한 대로 `requirements.txt`의 버전 조건을 파이토치 설치에도 똑같이 적용하는 옵션이다. 이것이 없으면 인덱스의 최신 버전이 설치되고, 다음 명령인 `pip install -r requirements.txt`가 그 버전을 지우고 **PyPI의 기본 설치본으로 바꿔 버릴 수 있다.** `--upgrade`는 7절에서 이미 CPU용 파이토치를 설치했더라도 CUDA용으로 교체하도록 한다.

파이토치를 먼저, `requirements.txt`를 나중에 설치한다. 두 명령의 버전 조건이 같으므로 두 번째 명령은 방금 설치한 CUDA용 파이토치를 그대로 둔다.

### 확인

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

`2.12.1+cu132 True`처럼 버전의 **끝이 `+cu132`이고** 두 번째 값이 **`True`** 로 나오면 성공이다. 끝에 `+cu132`가 없거나 `+cpu`라면 CUDA용이 아닌 파이토치가 설치된 것이므로 위의 설치 명령을 다시 실행한다.

**`False`가 나온다면** 드라이버가 지원하는 것보다 높은 CUDA 버전을 설치한 경우가 대부분이다. 한 단계 낮은 버전으로 다시 설치한다.

```bash
pip install --force-reinstall -c requirements.txt torch torchvision \
    --index-url https://download.pytorch.org/whl/cu130
```

### 참고: 그래픽 메모리가 모자랄 때

12장과 13장은 모델이 커서 그래픽 메모리를 많이 사용한다. `CUDA out of memory` 오류를 만나면 이렇게 대처한다.

- **배치 크기를 줄인다.** 노트북 위쪽의 `BATCH_SIZE`를 절반으로 낮춰 본다.
- **다른 노트북의 커널을 종료한다.** 이전에 실행한 노트북이 메모리를 쥐고 있는 경우가 흔하다. `nvidia-smi`로 확인할 수 있다.
- **윈도우 쪽에서 그래픽 카드를 사용하는 프로그램을 닫는다.** WSL2는 그래픽 메모리를 윈도우와 나눠 사용한다. 학습 중에는 게임이나 영상 편집 프로그램을 닫아 두자.
- 그래도 그래픽 메모리가 부족한 경우 CPU를 실습에 사용하거나, 구글 코랩 사용을 고려해보길 권한다.

## 10. WSL2에서 알아 둘 것

### 메모리 사용량 조절

WSL2는 기본적으로 윈도우가 가진 메모리의 절반까지 사용한다. 큰 모델을 다루다 메모리가 모자라면 윈도우 쪽 사용자 폴더(`C:\Users\사용자`)에 `.wslconfig`라는 파일을 만들어 조절한다.

```ini
[wsl2]
memory=16GB
```

파일을 만든 뒤 PowerShell에서 `wsl --shutdown`을 실행하고 Ubuntu를 다시 열면 반영된다.

### 윈도우와 파일 주고받기

가끔 윈도우 쪽 파일을 리눅스로 가져오거나 그 반대가 필요할 때가 있다.

| 방향 | 방법 |
|---|---|
| 윈도우 → 리눅스 | Ubuntu 터미널에서 `/mnt/c/Users/사용자/...` 경로로 접근 |
| 리눅스 → 윈도우 | 윈도우 탐색기 주소창에 `\\wsl$\Ubuntu-24.04\home\사용자` 입력 |

**작업 폴더 자체를 윈도우 쪽에 두지는 말자.** 앞에서 말한 대로 느려진다. 파일을 옮길 때만 사용한다.

### 자주 사용하는 WSL 명령

PowerShell에서 실행한다.

| 하고 싶은 일 | 명령 |
|---|---|
| 설치된 배포판 목록 | `wsl -l -v` |
| WSL 종료 | `wsl --shutdown` |
| 기본 배포판 지정 | `wsl --set-default Ubuntu-24.04` |

설정을 바꾸었거나 리눅스 쪽이 이상할 때 `wsl --shutdown` 후 다시 여는 것만으로 해결되는 경우가 많다.

## 11. 자주 만나는 문제

| 증상 | 원인과 해결 |
|---|---|
| `wsl --install` 명령이 실패한다 | PowerShell을 관리자 권한으로 실행했는지, 윈도우 버전이 요건을 만족하는지, 가상화가 켜져 있는지 확인한다(2절 '설치 요건'). 윈도우 업데이트가 필요할 수도 있다 |
| 비밀번호를 입력해도 화면에 안 보인다 | 정상이다. 리눅스는 비밀번호 입력을 표시하지 않는다 |
| `ensurepip is not available` 오류로 가상 환경이 만들어지지 않는다 | 실행한 파이썬 버전에 맞는 `venv` 패키지가 없다. 오류 메시지가 알려 주는 `python3.XX-venv`를 설치한다. 기본 파이썬은 `python3-venv`, deadsnakes로 설치한 3.14는 `python3.14-venv`다(3절) |
| `externally-managed-environment` 오류 | 가상 환경을 활성화하지 않았다. `source .venv/bin/activate` |
| `ModuleNotFoundError: No module named 'torch'` | 커널로 `.venv`를 고르지 않았거나, 가상 환경 밖에서 설치했다 |
| VS Code 왼쪽 아래에 `WSL`이 안 보인다 | WSL 확장이 없거나, 터미널에서 `code .`로 열지 않았다 |
| 커널 목록에 윈도우 경로만 나온다 | 같은 원인. WSL 확장을 설치하고 `code .`로 다시 연다 |
| 그래프의 한글이 네모로 보인다 | 글꼴 설치 후 커널을 다시 시작하지 않았다(8절) |
| 학습이 유난히 느리다 | 저장소를 `/mnt/c/` 아래에 두었는지 확인한다. 홈 폴더로 옮긴다 |
| `torch.__version__`에 `+cpu`(CPU) 또는 `+cu132`(CUDA)가 붙지 않는다 | `pip install -r requirements.txt`가 파이토치를 PyPI 기본 설치본으로 바꿨다. 파이토치 설치 명령에 `-c requirements.txt`를 붙여 다시 설치한다(7절, 9절) |
| 파이토치 설치 용량이 몇 GB다(CPU 사용 시) | CPU용 경로를 지정하지 않았거나, 파이토치 설치 명령에 `-c requirements.txt`를 빠뜨렸다(7절) |
| `nvidia-smi`가 동작하지 않는다 | 윈도우 쪽 드라이버를 확인한다. 리눅스 안에 드라이버를 설치하지 않는다(9절) |
| `torchvision` 설치가 거부되거나 `__annotate__` 오류가 난다 | 파이썬 **3.14.1**의 알려진 문제다. 3.14.2 이상으로 올린다 |
