# 맥에서 실습 환경 준비하기

> AI가 자동 생성한 후, 저자가 검토, 수정한 파일임을 밝혀 둡니다.

> **대상** 맥을 사용하는 독자. **M1 이후의 애플 실리콘 칩**을 기준으로 설명한다.
>
> 인텔 칩을 쓰는 맥은 최신 버전의 파이토치를 지원하지 않으므로 대상으로 하지 않는다.

전체 과정은 이렇다.

1. 개발 도구와 홈브루 준비
2. 파이썬 설치
3. VS Code와 확장 설치
4. 예제 저장소 내려받기
5. 가상 환경 만들기
6. 파이토치와 라이브러리 설치
7. 노트북 실행

맥에서 GPU를 사용하는 방법과 주의 사항은 **8절 'MPS로 GPU 사용하기'** 에 따로 정리했다.

## 1. 개발 도구와 홈브루 준비

### 명령행 개발 도구

맥에는 개발에 필요한 기본 도구가 처음부터 들어 있지 않다. 터미널을 열고 다음을 실행한다.

터미널은 **응용 프로그램 → 유틸리티 → 터미널**에 있다. 스포트라이트(`Command + Space`)에서 '터미널'을 입력해도 된다.

```bash
xcode-select --install
```

설치 창이 뜨면 안내를 따른다. 이미 설치되어 있다면 그렇다는 메시지가 나오는데, 그대로 다음으로 넘어가면 된다.

이 과정에서 **Git**도 함께 설치된다. Git은 소스 코드의 변경 이력을 관리하는 도구로, 이 책에서는 예제 저장소를 내려받고 나중에 갱신하는 데 사용한다.

### 홈브루

**홈브루**(Homebrew)는 맥에서 널리 사용하는 패키지 관리자다. 명령 한 줄로 프로그램을 설치하고 갱신할 수 있다. 파이썬을 설치하는 데 사용하므로 먼저 준비하자.

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

설치가 끝나면 화면에 안내가 몇 줄 나온다. **경로를 설정하라는 내용이 있으면 그대로 따라 실행한다.** 애플 실리콘 맥에서는 보통 이런 내용이다.

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

설치를 확인한다.

```bash
brew --version
```

## 2. 파이썬 설치

맥에는 파이썬이 기본으로 들어 있다. 하지만 **그것을 사용하지는 말자.** `/usr/bin/python3`에 있는 파이썬은 맥OS가 내부적으로 사용하는 것이라, 여기에 패키지를 설치하면 시스템에 영향을 줄 수 있다. 버전도 선택할 수 없다.

홈브루로 따로 설치한다. 이 책은 **3.12 이상 3.14 이하**를 지원한다.

```bash
brew install python@3.14
python3.14 --version
```

> **설치 중 오류가 난다면** 홈브루와 맥OS를 최신으로 올린 뒤 다시 시도해 보자. 맥OS를 새 버전으로 올린 직후에는 홈브루가 제공하는 패키지가 아직 맞춰지지 않아 문제가 생기는 경우가 있다.
>
> ```bash
> brew update && brew upgrade
> ```

## 3. VS Code와 확장 설치

[VS Code 내려받기 페이지](https://code.visualstudio.com/)에서 맥용을 받는다. 받은 파일의 압축을 풀면 나오는 앱을 **응용 프로그램** 폴더로 옮긴다.

VS Code를 실행한 뒤 확장을 설치한다.

1. 왼쪽 세로 막대에서 **확장**(Extensions) 아이콘을 누른다. 네모 블록 네 개가 모인 모양이고, 단축키는 `Command + Shift + X`다.
2. 검색창에 확장 이름을 입력하고, **마이크로소프트(Microsoft)가 배포한 것**을 골라 설치한다. 이름이 같은 확장이 여러 개 보일 수 있으므로 배포자를 확인한다.

설치할 확장은 다음과 같다.

| 확장 | 역할 |
|---|---|
| **Python** | 파이썬 문법 강조, 자동 완성, 가상 환경 인식 |
| **Jupyter** | 노트북 파일을 열고 셀을 실행 |

이 확장이 있어야 노트북 파일을 열고 셀을 실행할 수 있다. 메뉴를 한국어로 보고 싶다면 **Korean Language Pack**도 함께 설치한다.

터미널에서 `code .`로 VS Code를 열 수 있게 해 두면 편하다. VS Code에서 `Command + Shift + P`를 누르고 `shell command`를 입력한 뒤 **'Shell Command: Install code command in PATH'** 를 고른다.

## 5. 가상 환경 만들기

### 가상 환경이란

파이썬 프로젝트마다 필요한 라이브러리와 버전이 다르다. 모든 라이브러리를 한곳에 설치하면 프로젝트끼리 버전이 충돌한다. A 프로젝트는 파이토치 2.12가 필요한데 B 프로젝트는 2.8이 필요한 상황이 생기는 것이다.

**가상 환경**(virtual environment)은 프로젝트마다 라이브러리를 담는 상자를 따로 두는 장치다. 이 책의 라이브러리를 이 책 전용 상자에 담아 두면 다른 프로젝트에 영향을 주지도 받지도 않는다. 상자를 통째로 지우고 다시 만들 수도 있어서 설치가 꼬였을 때 되돌리기도 쉽다.

### 만들고 활성화하기

저장소 폴더(`~/dl-pytorch`)에서 실행한다.

```bash
python3.14 -m venv .venv
source .venv/bin/activate
```

성공하면 프롬프트 앞에 `(.venv)`가 붙는다.

```
(.venv) 사용자@맥 dl-pytorch %
```

**이후의 모든 명령은 이 상태에서 실행한다.**

### 가상 환경 사용법

| 하고 싶은 일 | 명령 |
|---|---|
| 활성화 | `source .venv/bin/activate` |
| 비활성화 | `deactivate` |
| 지금 활성화되어 있는지 확인 | 프롬프트 앞의 `(.venv)` 표시를 본다 |
| 어느 파이썬을 사용하는지 확인 | `which python` |
| 통째로 지우기 | `deactivate` 후 `rm -rf .venv` |

**터미널을 새로 열 때마다 활성화해야 한다.** 활성화하지 않은 채로 설치하면 엉뚱한 곳에 들어간다. 잘 되던 것이 갑자기 안 될 때 가장 먼저 확인할 것이 `(.venv)` 표시다.

> 위의 예제에서 .venv는 가상환경의 이름인 동시에, 가상 환경 실행에 필요한 파일이 저장되는 디렉터리의 이름이다. 경우에 따라서는 같은 프로젝트에 서로 다른 조합의 라이브러리를 사용해야 할 때도 있다. 예를 들어 CUDA 적용 환경과 CUDA 비적용 환경을 함께 사용한다면, 같은 디렉터리에서 이름이 다른 두 개의 가상 환경을 만들어 사용하면 된다. .venv와 .venv_cuda 두 개의 가상 환경을 만든 경우, .venv에 설치된 라이브러리는 .venv_cuda에 영향을 주지 않으며, 사용할 수도 없고, 그 반대 방향도 성립한다.

## 6. 파이토치와 라이브러리 설치

가상 환경이 활성화된 상태에서 명령 하나면 끝난다.

```bash
pip install -r requirements.txt
```

`requirements.txt`는 저장소에 들어 있는 파일로, 필요한 라이브러리와 버전이 적혀 있다. 파이토치와 기본 라이브러리가 설치된다.

맥에서는 설치 경로를 따로 지정할 것이 없다. **맥용 파이토치에는 GPU를 사용하는 기능이 처음부터 들어 있다.** 리눅스나 윈도우에서 CUDA 버전을 골라 설치해야 하는 것과 다른 점이다.

### 설치 확인

```bash
python -c "import torch; print(torch.__version__)"
```

`2.12.0`처럼 출력되면 성공이다. GPU를 사용할 수 있는지는 8절에서 확인한다.

### pip 사용법

책을 진행하면서 절마다 추가 라이브러리를 설치하게 되므로 몇 가지만 알아 두자.

| 하고 싶은 일 | 명령 |
|---|---|
| 설치 | `pip install 패키지이름` |
| 여러 개 한 번에 | `pip install 패키지1 패키지2` |
| 파일에 적힌 목록대로 | `pip install -r requirements.txt` |
| 버전을 지정해 설치 | `pip install "패키지이름>=1.2"` |
| 설치된 목록 보기 | `pip list` |
| 특정 패키지 정보 보기 | `pip show 패키지이름` |
| 삭제 | `pip uninstall 패키지이름` |

**버전을 지정할 때는 따옴표로 감싸자.** 따옴표가 없으면 `>` 기호를 셸이 '출력을 파일로 보내라'는 뜻으로 해석해, 버전 조건은 무시되고 이상한 이름의 빈 파일이 만들어진다.

## 8. MPS로 GPU 사용하기

### MPS란

맥에는 NVIDIA 그래픽 카드가 들어가지 않는다. 그래서 CUDA를 사용할 수 없다. 대신 애플이 제공하는 **MPS**(Metal Performance Shaders)라는 기술로 맥에 내장된 GPU를 사용한다.

파이토치는 MPS를 지원한다. 코드에서 장치를 `'mps'`로 지정하면 GPU로 계산한다. 이 책의 노트북은 공통 라이브러리의 `common.get_device()`가 알아서 골라 주므로 자동으로 알맞은 연산 장치 객체가 생성된다.

맥에서 노트북을 실행하면 이렇게 출력된다.

```
MPS를 사용합니다.
```

다만, 일부 예제는 파이토치의 지원 미비로 mps 장치에서 제대로 실행되지 않는 문제가 있다. 이 경우 다음과 같이 cpu를 연산 장치로 사용해야 한다.

```
device = torch.device('cpu')
```

### 사용할 수 있는지 확인

```bash
python -c "import torch; print(torch.backends.mps.is_available())"
```

`True`가 나오면 준비된 것이다. 실제로 계산이 되는지 확인하려면 이렇게 한다.

```bash
python -c "
import torch
x = torch.randn(1000, 1000, device='mps')
print((x @ x).shape, x.device)"
```

### 속도

MPS는 CPU보다 확실히 빠르다. 다만 비슷한 가격대의 NVIDIA 그래픽 카드에는 미치지 못한다. 1장부터 7장까지는 쾌적하고, 8장 이후는 기다림이 길어진다.

맥은 CPU와 GPU가 메모리를 함께 사용하는 **통합 메모리** 구조다. 그래서 **메모리가 넉넉한 모델일수록 큰 모델을 다루기 수월하다.** 12장과 13장처럼 큰 모델을 다루는 장에서 차이가 난다.

### 결과의 미세한 차이

이 책의 노트북에 저장된 출력은 NVIDIA 그래픽 카드 환경에서 만든 것이다. MPS에서는 계산 순서가 달라 손실값이나 정확도의 마지막 자리가 다를 수 있다. **학습의 경향과 결론은 같게 유지되므로 신경 쓰지 않아도 된다.

## 9. 맥에서 발생 가능한 문제

MPS는 CUDA만큼 오래된 기술이 아니다. 그래서 아직 지원하지 않는 기능이 있고, 드물게 문제가 생기는 자리도 있다.

**대부분의 절은 그냥 실행하면 된다.** 아래는 미리 알아 두면 좋은 내용이다. 지금 다 읽을 필요는 없고, 해당 절에서 문제가 생겼을 때 다시 찾아보면 된다.

### 지원하지 않는 연산을 만났을 때

파이토치의 연산 중 일부는 아직 MPS에 구현되어 있지 않다. 그런 연산을 만나면 이런 오류가 난다.

```
NotImplementedError: The operator 'aten::...' is not currently
implemented for the MPS device.
```

이때 **그 연산만 CPU로 처리하도록** 하는 설정이 있다. 노트북의 가장 첫 셀에 다음을 넣고 커널을 다시 시작한다.

```python
import os
os.environ['PYTORCH_ENABLE_MPS_FALLBACK'] = '1'
```

> 다만 이 방법은 **그 연산 하나만 CPU로 옮기는 것이 아닐 수 있다.** 그 연산이 다른 미구현 연산을 불러들이면 연쇄적으로 CPU로 내려가 조용히 느려진다. 아래 10-1절처럼 더 정확한 대처가 있다면 그것을 먼저 사용하자.

### 9-1절 — 자동으로 CPU를 사용한다

9-1절의 모델은 데이터를 하나씩 처리하면서 토큰도 하나씩 생성하는 구조다. 배치 크기와 시퀀스 길이가 모두 1인 LSTM을 역전파할 때 MPS에서 문제가 생겨, MPS로 실행하면 오류 메시지 없이 커널이 죽는다.

그래서 9-1절 예제 노트북은 MPS가 감지되면 자동으로 CPU를 사용하도록 만들어 두었다. 따로 할 일은 없다.

다만, 9-1절 예제의 특성 상 성능 차이가 거의 없다. 이 절은 데이터를 하나씩 처리하고 모델도 작아서, 이 규모에서는 CPU가 오히려 빠를 수 있다.

9-2절과 9-3절은 데이터를 여러 개씩 묶어 처리하므로 영향이 없다. MPS에서 그대로 실행하면 된다.

### 10-1절 — 한 줄을 추가한다

학습을 시작하면 첫 에포크의 **검증 단계**에서 멈춘다.

```
NotImplementedError: The operator 'aten::_nested_tensor_from_mask_left_aligned'
is not currently implemented for the MPS device.
```

트랜스포머 인코더에는 계산량을 줄이는 최적화 경로가 있는데, 그 경로가 MPS에 없는 연산을 사용한다. 이 경로는 평가할 때만 조건이 맞아서, 학습은 통과하고 검증에서 걸린다. 그래서 원인을 학습 코드에서 찾게 되기 쉽다.

시드를 고정하는 셀에 다음 한 줄을 추가하면 그 경로를 사용하지 않는다.

```python
torch.backends.mha.set_fastpath_enabled(False)
```

연산은 모두 MPS에 남으므로 속도 손실이 없다. 앞에서 설명한 `PYTORCH_ENABLE_MPS_FALLBACK`보다 이 방법이 정확하다.

10-2절과 10-3절은 같은 최적화를 이미 끄고 있어 영향이 없다.

### 12-3절 — 메모리 수치가 0으로 나온다

실행은 정상이다. 모델도 불러오고 답변도 생성된다. 다만 메모리 사용량을 비교하는 부분이 이렇게 나온다.

```
양자화 모델 메모리   : 0 MB
비양자화 모델 메모리 : 0 MB
```

노트북의 측정 함수가 CUDA용 함수를 사용하기 때문이다. MPS에는 대응하는 함수가 따로 있다.

```python
torch.mps.current_allocated_memory() / 1024 / 1024   # MB 단위
```

측정 부분을 이렇게 바꾸면 수치를 볼 수 있다. 메모리를 비우는 부분도 `torch.mps.empty_cache()`를 함께 호출해야 두 모델의 측정값이 섞이지 않는다.

> 본문의 '12-3절의 예제 실행 환경' 박스에는 양자화에 사용하는 `bitsandbytes` 라이브러리가 애플 실리콘(MPS)도 지원하지만 일부 기능은 아직 불안정하다고 적혀 있다. 지금은 이 절의 예제가 MPS에서도 정상적으로 실행된다. 다만 CUDA 환경이 가장 빠르다는 점은 그대로이므로, 속도가 중요하다면 [구글 코랩](google-colab.md)의 GPU 런타임도 좋은 선택이다.

### 13-2절 — 메모리가 넉넉해야 한다

13-2절에서 사용하는 모델은 16비트로 불러도 7GB가 넘는다. 통합 메모리가 부족하면 파이토치가 일부를 디스크에 두고 사용하는데, 그러면 토큰을 하나 생성할 때마다 디스크를 읽느라 **수십 배 느려진다.**

다른 앱을 모두 닫고 실행하면 나아진다. 모델이 어디에 올라갔는지는 이렇게 확인할 수 있다.

```python
print(getattr(model, 'hf_device_map', None))
```

출력에 `'disk'`나 `'cpu'`가 섞여 있으면 메모리가 부족한 상태다. 메모리가 16GB인 기기라면 이 절만 [구글 코랩](google-colab.md)에서 실행하는 편이 편하다.

## 10. 자주 만나는 문제

| 증상 | 원인과 해결 |
|---|---|
| `brew` 명령을 찾을 수 없다 | 설치 후 안내된 경로 설정을 실행하지 않았다(1절) |
| `ModuleNotFoundError: No module named 'torch'` | 커널로 `.venv`를 고르지 않았거나, 가상 환경 밖에서 설치했다 |
| `ModuleNotFoundError: No module named 'code_reference'` | VS Code에서 저장소 최상위가 아닌 다른 폴더를 열었다 |
| 커널 목록에 `.venv`가 없다 | VS Code를 다시 시작한다. 그래도 없으면 폴더를 제대로 열었는지 확인한다 |
| `mps.is_available()`이 `False` | 인텔 맥이거나 맥OS 버전이 낮다. CPU로 진행하면 된다 |
| `NotImplementedError: aten::...` | MPS에 없는 연산이다. 9절 참고 |
| 9-1절에서 커널이 죽는다 | 알려진 문제다. CPU로 지정한다(9절) |
| 학습이 유난히 느리다 | 메모리가 모자라 디스크를 사용하고 있을 수 있다. 다른 앱을 닫는다 |
| 파이썬 설치 중 오류 | `brew update && brew upgrade` 후 다시 시도한다 |
| `torchvision` 설치가 거부되거나 `__annotate__` 오류가 난다 | 파이썬 **3.14.1**의 알려진 문제다. 3.14.2 이상으로 올린다 |
