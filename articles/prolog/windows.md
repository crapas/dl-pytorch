## 1. 파이썬 설치

### 파이썬이 이미 설치되어 있는지 확인

파워셸(PowerShell) 환경으로 들어간다. 대부분의 경우 터미널 앱을 실행하면 파워셸 환경으로 들어갈 수 있다.

```powershell
python --version
```

`Python 3.12.x`부터 `Python 3.14.x` 사이의 버전이 출력되면 이미 준비된 것이다.

명령을 찾을 수 없다는 메시지가 나오거나, 버전이 표시되지 않거나, 버전이 범위를 벗어나면 새로 설치한다.

> 윈도우에서 `python`을 입력했을 때 마이크로소프트 스토어가 열리는 경우가 있다. 파이썬이 설치되어 있지 않을 때 윈도우가 보여 주는 안내 화면이다. 이 화면에서 설치해도 되지만, 권한 처리 방식 때문에 가상 환경이나 패키지 설치에서 문제가 생기는 경우가 있어 권하지 않는다. 아래 방법으로 설치하자.

### 내려받아 설치하기

[python.org의 윈도우 내려받기 페이지](https://www.python.org/downloads/windows/)에서 **3.12 이상 3.14 이하** 버전을 받는다. 특별한 이유가 없다면 그 범위에서 가장 높은 버전을 받으면 된다.

내려받은 설치 프로그램을 실행하면 첫 화면에 체크 상자가 몇 개 보인다. 여기서 **`Add python.exe to PATH`를 반드시 체크한다.**

이것을 빠뜨리면 PowerShell에서 `python`을 입력해도 찾지 못한다. 윈도우가 프로그램을 찾는 경로 목록에 파이썬이 등록되지 않기 때문이다. 체크했다면 `Install Now`를 눌러 설치한다.

설치가 끝나면 **PowerShell 창을 닫았다가 새로 연 뒤** 확인한다. 기존 터미널에서는 경로 설정(Add python.exe to PATH)이 반영되지 않을 수 있다.

```powershell
python --version
```

> 현재 파이썬의 최신 버전은 파이썬 3.15.0이지만, 아직 이 버전의 파이썬에서 예제 코드의 실행 여부를 확인하기 전이다. 확인 후 이 문서를 수정할 예정이다.

## 2. VS Code와 확장 설치

[VS Code 내려받기 페이지](https://code.visualstudio.com/)에서 윈도우용 설치 프로그램을 받아 설치한다. 설치 중 선택 항목이 나오면 기본값 그대로 두어도 된다.

VS Code를 실행한 뒤 확장을 설치한다.

1. 왼쪽 세로 막대에서 **확장**(Extensions) 아이콘을 누른다. 네모 블록 네 개가 모인 모양이고, 단축키는 `Ctrl+Shift+X`다.
2. 검색창에 확장 이름을 입력하고, **마이크로소프트(Microsoft)가 배포한 것**을 골라 설치한다. 이름이 같은 확장이 여러 개 보일 수 있으므로 배포자를 확인한다.

설치할 확장은 다음과 같다.

| 확장 | 역할 |
|---|---|
| **Python** | 파이썬 문법 강조, 자동 완성, 가상 환경 인식 |
| **Jupyter** | 노트북 파일을 열고 셀을 실행 |

이 확장이 있어야 노트북 파일을 열고 셀을 실행할 수 있다. 메뉴를 한국어로 보고 싶다면 **Korean Language Pack**도 함께 설치한다.

## 3. 예제 저장소 내려받기

예제 코드를 받는 방법은 두 가지다.

### 방법 1 — Git 사용하기 (권장)

**Git**은 소스 코드의 변경 이력을 관리하는 도구다. 이 방법으로 받아 두면 나중에 예제가 수정되었을 때 명령 한 번으로 갱신할 수 있다.

먼저 이미 설치되어 있는지 확인한다.

```powershell
git --version
```

`git version 2.x.x`처럼 출력되면 2단계로 넘어간다. 명령을 찾을 수 없다면 설치한다.

[Git for Windows](https://git-scm.com/download/win)에서 설치 프로그램을 받는다. 설치 중 선택 항목이 많지만 **모두 기본값으로 두어도 된다.** 기본값을 바꾸지 않는 편이 오히려 안전하다.

설치가 끝나면 **PowerShell 창을 닫았다가 새로 연다.** 경로 설정은 새로 연 창부터 반영된다.

```powershell
git --version
```

버전이 출력되면 예제를 둘 폴더로 이동한 뒤 내려받는다. 다음의 C:\dev 대신 각자 실습에 사용할 디렉터리를 입력해도 된다.

```powershell
cd C:\dev
git clone https://github.com/crapas/dl-pytorch.git
cd dl-pytorch
```

`C:\dev` 폴더가 없다면 `mkdir C:\dev`로 먼저 만든다.

> **저장소를 두는 위치에 주의하자.** 윈도우에는 파일 경로의 길이를 260자로 제한하는 규칙이 있다. 저장소를 `C:\Users\사용자\Documents\...`처럼 깊은 곳에 두면 일부 패키지를 설치할 때 이 제한에 걸릴 수 있다. `C:\dev`처럼 짧은 경로를 권한다.

나중에 예제를 갱신하려면 저장소 폴더에서 다음을 실행한다.

```powershell
git pull
```

### 방법 2 — 압축 파일로 받기

Git을 설치하고 싶지 않다면 [저장소 페이지](https://github.com/crapas/dl-pytorch)에서 녹색 **`Code`** 단추를 누르고 **`Download ZIP`** 을 고른다. 받은 압축 파일을 `C:\dev` 아래에 풀면 된다.

다만 이 방법은 예제가 수정할 때마다 다시 받아야 하므로 권장하지 않는다. 

> 예제가 수정되거나 콘텐츠가 추가될 때 마다 새로 내려받는 대신 Git을 사용해 저장소와 동기화하면서 사용하는 방식을 추천한다. 이를 위해서는 Git 사용법을 익혀두는 것이 좋다.

## 4. 가상 환경 만들기

### 가상 환경이란

파이썬 프로젝트마다 필요한 라이브러리와 버전이 다르다. 모든 라이브러리를 한곳에 설치하면 프로젝트끼리 버전이 충돌한다. A 프로젝트는 파이토치 2.12가 필요한데 B 프로젝트는 2.8이 필요한 상황이 생기는 것이다.

**가상 환경**(virtual environment)은 프로젝트마다 라이브러리를 담는 상자를 따로 두는 장치다. 이 책의 라이브러리를 이 책 전용 상자에 담아 두면, 다른 프로젝트에 영향을 주지도 받지도 않는다. 상자를 통째로 지우고 다시 만들 수도 있어서 설치가 꼬였을 때 되돌리기도 쉽다.

### 만들고 활성화하기

저장소 폴더(`C:\dev\dl-pytorch`)에서 실행한다.

```powershell
python -m venv .venv
```

`.venv`라는 폴더가 생긴다. 이 안에 파이썬과 라이브러리가 들어간다. 이제 이 환경을 **활성화**한다.

```powershell
.venv\Scripts\activate
```

성공하면 프롬프트 앞에 `(.venv)`가 붙는다.

```
(.venv) PS C:\dev\dl-pytorch>
```

**이후의 모든 명령은 이 상태에서 실행한다.**

> **PowerShell에서 오류가 날 때.** `이 시스템에서 스크립트를 실행할 수 없으므로`라는 메시지가 나오면, 윈도우가 보안을 위해 스크립트 실행을 막고 있는 것이다. 현재 사용자에 한해 허용하면 된다.
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```
>
> 그다음 활성화 명령을 다시 실행한다.

### 가상 환경 사용법

| 하고 싶은 일 | 명령 |
|---|---|
| 활성화 | `.venv\Scripts\activate` |
| 비활성화 | `deactivate` |
| 지금 활성화되어 있는지 확인 | 프롬프트 앞의 `(.venv)` 표시를 본다 |
| 통째로 지우기 | 창을 닫고 `.venv` 폴더를 삭제한다 |

**PowerShell 창을 새로 열 때마다 활성화해야 한다.** 활성화하지 않은 채로 설치하면 라이브러리가 엉뚱한 곳에 들어간다. 잘 되던 것이 갑자기 안 될 때 가장 먼저 확인할 것이 `(.venv)` 표시다.

> 위의 예제에서 .venv는 가상환경의 이름인 동시에, 가상 환경 실행에 필요한 파일이 저장되는 디렉터리의 이름이다. 경우에 따라서는 같은 프로젝트에 서로 다른 조합의 라이브러리를 사용해야 할 때도 있다. 예를 들어 CUDA 적용 환경과 CUDA 비적용 환경을 함께 사용한다면, 같은 디렉터리에서 이름이 다른 두 개의 가상 환경을 만들어 사용하면 된다. .venv와 .venv_cuda 두 개의 가상 환경을 만든 경우, .venv에 설치된 라이브러리는 .venv_cuda에 영향을 주지 않으며, 사용할 수도 없고, 그 반대 방향도 성립한다.

## 5. 파이토치와 라이브러리 설치

### NVIDIA 그래픽 카드가 없는 경우

가상 환경이 활성화된 상태에서 명령 하나면 끝난다.

```powershell
pip install -r requirements.txt
```

`requirements.txt`는 저장소에 들어 있는 파일로, 필요한 라이브러리와 버전이 적혀 있다. 프롤로그 1-5절의 도구 중 파이토치와 기본 라이브러리가 설치된다. 내려받을 용량이 수백 MB 정도라 몇 분 걸릴 수 있다.

> 윈도우용 파이토치는 기본 설치본이 CPU 전용이라 따로 지정할 것이 없다. 뒤에 나오는 리눅스나 맥과 다른 점이다.

### NVIDIA 그래픽 카드가 있는 경우

**7절을 먼저 읽자.** 설치 방법에 차이가 있다.

### pip 사용법

`pip`는 파이썬 패키지를 설치하는 도구다. 책을 진행하면서 절마다 추가 라이브러리를 설치하게 되므로 몇 가지만 알아 두자.

| 하고 싶은 일 | 명령 |
|---|---|
| 설치 | `pip install 패키지이름` |
| 여러 개 한 번에 | `pip install 패키지1 패키지2` |
| 파일에 적힌 목록대로 | `pip install -r requirements.txt` |
| 버전을 지정해 설치 | `pip install "패키지이름>=1.2"` |
| 설치된 목록 보기 | `pip list` |
| 특정 패키지 정보 보기 | `pip show 패키지이름` |
| 삭제 | `pip uninstall 패키지이름` |

**버전을 지정할 때는 따옴표로 감싸야 한다.** 따옴표가 없으면 `>` 기호를 PowerShell이 다른 뜻으로 해석해 엉뚱한 파일이 만들어진다.

## 6. 설치 확인과 노트북 실행

### 설치 확인

가상 환경이 활성화된 상태에서 실행한다.

```powershell
python -c "import torch; print(torch.__version__)"
```

`2.12.0`처럼 버전이 출력되면 성공이다.

### 노트북 실행

1. VS Code를 실행하고 **파일 → 폴더 열기**로 `C:\dev\dl-pytorch`를 연다.
2. 왼쪽 탐색기에서 `code_examples` → `ch01` → `01-01_example.ipynb`를 연다.
3. **오른쪽 위의 '커널 선택'을 누르고 방금 만든 `.venv`를 고른다.** 목록에 `.venv (Python 3.x.x)`처럼 표시된다.
> 다른 이름으로 가상환경을 생성한 경우, .venv 대신 다른 이름의 가상 환경을 선택하면 된다.
4. 첫 셀 왼쪽의 실행 단추를 누르거나 `Shift+Enter`를 눌러 위에서 아래로 차례대로 실행한다.

**3번이 가장 중요하다.** 커널은 노트북의 코드를 실제로 실행하는 파이썬을 가리킨다. 가상 환경이 아닌 다른 파이썬을 고르면 설치한 라이브러리를 찾지 못해 `ModuleNotFoundError`가 난다.

> 커널 목록에 `.venv`가 보이지 않으면 VS Code를 다시 시작해 보자. 그래도 없다면 폴더를 제대로 열었는지(저장소 최상위 폴더여야 한다), 가상 환경을 만든 위치가 맞는지 확인한다.

### 한글 그래프

노트북은 그래프에 한글을 사용한다. 예제 노트북의 그래프에서 사용하는 기본 한글 폰트인 맑은 고딕체가 윈도우에 기본 설치되어 있어 따로 설치할 필요가 없다.

## 7. NVIDIA 그래픽 카드 사용하기

> NVidia 그래픽 카드가 없거나 사용하지 않을 생각이라면 이 절을 건너뛰어도 된다.

### CUDA란

**CUDA**는 NVIDIA가 만든 기술로, 그래픽 카드로 일반적인 계산을 수행할 수 있게 해 준다. 딥러닝의 학습은 같은 계산을 엄청나게 많이 되풀이하는 작업이라 CPU보다 그래픽 카드가 훨씬 빠르다. 모델에 따라 수십 배 차이가 난다.

파이토치는 CUDA를 사용하는 설치본을 따로 제공한다. 이것을 설치하면 코드를 거의 바꾸지 않고도 그래픽 카드로 학습할 수 있다.

### NVIDIA 그래픽 드라이버만 확인하자

인터넷을 찾아보면 'CUDA 툴킷을 설치하라'는 안내가 많은데, **파이토치를 사용할 목적이라면 CUDA 툴킷을 따로 설치할 필요가 없다.** 필요한 CUDA 라이브러리가 파이토치 설치본 안에 들어 있기 때문이다.

준비할 것은 **NVIDIA 그래픽 드라이버** 하나다. 대부분의 컴퓨터에는 이미 설치되어 있다.

### 드라이버 확인

PowerShell에서 실행한다.

```powershell
nvidia-smi
```

표가 출력되면 준비된 것이다. **표 오른쪽 위의 `CUDA Version:` 값을 적어 두자.** 다음 단계에서 사용한다.

이 값은 "이 드라이버가 지원하는 CUDA의 최대 버전"을 뜻한다. CUDA가 설치되어 있다는 뜻이 아니다.

명령을 찾을 수 없다면 드라이버가 없거나 오래된 것이다. [NVIDIA 드라이버 페이지](https://www.nvidia.com/Download/index.aspx)에서 자신의 그래픽 카드에 맞는 최신 드라이버를 받아 설치하고 다시 확인한다.

### 파이토치 설치

파이토치는 CUDA 버전별로 설치본을 따로 제공한다. **드라이버가 지원하는 CUDA 버전보다 높은 것을 설치하면 동작하지 않으므로**, 앞에서 확인한 값보다 같거나 낮은 것을 고른다.

설치 명령은 [파이토치 공식 설치 안내 페이지](https://pytorch.org/get-started/locally/)에서 자신의 환경을 고르면 그 자리에서 만들어 준다. 운영체제, 설치 도구(Pip), 언어(Python), 연산 플랫폼(CUDA 버전)을 차례로 고르면 된다. **CUDA 버전은 `nvidia-smi`에서 확인한 값 이하의 것 중 가장 높은 것**을 고른다.

명령의 모양은 이렇다.

```powershell
pip install --upgrade -c requirements.txt torch torchvision --index-url https://download.pytorch.org/whl/cu132
pip install -r requirements.txt
```

`--index-url` 뒤의 주소가 "어디서 받을지"를 지정하는 부분이고, 끝의 `cu132`가 CUDA 13.2용이라는 뜻이다. 이 숫자가 버전에 따라 달라진다. 저장소 폴더(`C:\dev\dl-pytorch`)에서 실행한다.

**`-c requirements.txt`를 빼먹지 말자.** `-c`는 설치할 것을 정하지 않고 **버전의 범위만 제한**하는 옵션이다. `requirements.txt`는 `torch~=2.12.0`처럼 파이토치의 버전을 제한하고 있는데, 이 옵션이 없으면 CUDA용 인덱스의 가장 최신 버전이 설치된다. 그러면 다음 명령인 `pip install -r requirements.txt`가 그 버전을 지우고 **PyPI의 CPU 전용 파이토치로 바꿔 버린다.** 오류 없이 끝나기 때문에 알아차리기 어렵다. `-c requirements.txt`를 붙이면 두 명령이 같은 버전 조건을 따르므로 이런 일이 생기지 않는다.

`--upgrade`는 5절에서 이미 CPU용 파이토치를 설치했더라도 CUDA용으로 교체하도록 한다. 이 옵션이 없으면 "이미 설치되어 있다"며 아무것도 하지 않는다.

파이토치를 먼저, `requirements.txt`를 나중에 설치한다. 두 명령의 버전 조건이 같으므로 두 번째 명령은 방금 설치한 CUDA용 파이토치를 그대로 둔다.

### 확인

```powershell
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

`2.12.1+cu132 True`처럼 버전의 **끝이 `+cu132`이고** 두 번째 값이 **`True`** 로 나오면 성공이다. 버전에 `+cu132`가 없다면 CPU 전용 파이토치가 설치된 것이므로 위의 설치 명령을 다시 실행한다. 그래픽 카드 이름까지 확인하려면 이렇게 한다.

```powershell
python -c "import torch; print(torch.cuda.get_device_name(0))"
```

**`False`가 나온다면** 드라이버가 지원하는 것보다 높은 CUDA 버전을 설치한 경우가 대부분이다. 한 단계 낮은 버전으로 다시 설치한다.

```powershell
pip install --force-reinstall -c requirements.txt torch torchvision --index-url https://download.pytorch.org/whl/cu130
```

`--force-reinstall`은 이미 설치된 것을 지우고 새로 설치하라는 뜻이다.

### 참고: 그래픽 메모리가 모자랄 때

12장과 13장은 모델이 커서 그래픽 메모리를 많이 사용한다. `CUDA out of memory` 오류를 만나면 이렇게 대처한다.

- **배치 크기를 줄인다.** 노트북 위쪽의 `BATCH_SIZE`를 절반으로 낮춰 본다. 가장 효과가 확실하다.
- **다른 노트북의 커널을 종료한다.** 이전에 실행한 노트북이 메모리를 쥐고 있는 경우가 흔하다. VS Code에서 쓰지 않는 노트북을 닫고, `nvidia-smi`로 메모리를 차지한 프로세스를 확인한다.
- **그래픽 카드를 사용하는 다른 프로그램을 닫는다.** 게임이나 영상 편집 프로그램이 대표적이다.

그래도 모자라면 CPU를 사용하거나 해당 절만 [구글 코랩](google-colab.md)에서 실행하는 방법이 있다.

## 8. 자주 만나는 문제

| 증상 | 원인과 해결 |
|---|---|
| `python`을 찾을 수 없다 | 설치할 때 `Add python.exe to PATH`를 체크하지 않았다. 설치 프로그램을 다시 실행해 `Modify`로 수정하거나 재설치한다 |
| `python`을 입력하면 스토어가 열린다 | 파이썬이 설치되어 있지 않다. 1절대로 설치한다 |
| `이 시스템에서 스크립트를 실행할 수 없으므로` | PowerShell 실행 정책 문제. 4절의 `Set-ExecutionPolicy` 참고 |
| `ModuleNotFoundError: No module named 'torch'` | 커널로 `.venv`를 고르지 않았거나, 가상 환경을 활성화하지 않은 채 설치했다 |
| `ModuleNotFoundError: No module named 'code_reference'` | VS Code에서 저장소 최상위가 아닌 다른 폴더를 열었다. `dl-pytorch` 폴더를 열어야 한다 |
| 커널 목록에 `.venv`가 없다 | VS Code를 다시 시작한다. 그래도 없으면 폴더를 제대로 열었는지 확인한다 |
| 패키지 설치 중 경로가 길다는 오류 | 저장소를 `C:\dev`처럼 짧은 경로로 옮긴다 |
| `torch.__version__`에 `+cu132`가 붙지 않는다(CUDA 사용 시) | CPU 전용 파이토치가 설치되어 있다. 파이토치 설치 명령에 `--upgrade -c requirements.txt`를 붙여 다시 설치한다(7절) |
| `torch.cuda.is_available()`이 `False` | 드라이버보다 높은 CUDA 버전을 설치했다. 7절 참고 |
| 그래프의 한글이 네모로 보인다 | 노트북 커널을 다시 시작하고 처음부터 실행한다 |
| `torchvision` 설치가 거부되거나 `__annotate__` 오류가 난다 | 파이썬 **3.14.1**의 알려진 문제다. 3.14.2 이상으로 올린다 |
