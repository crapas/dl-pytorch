8-2절은 배치 정규화가 계층의 출력 분포를 다듬고 기울기 소실을 완화한다고 설명했고, [표 8-4]로 그 근거를 제시했다. 그 표의 숫자는 어디에서 왔을까? 모델 코드에는 기울기의 크기를 출력하는 줄이 한 줄도 없다. 이 글은 그 숫자를 만들어 낸 도구인 **파이토치 훅**(hook)을 다룬다.

훅은 모델을 만드는 일과 직접적인 관련은 없다. 하지만 모델이 뜻대로 학습되지 않을 때 원인을 찾는 거의 유일한 수단이고, 중간 특징을 꺼내 쓰는 여러 고급 기법의 토대이기도 하다.

## 1. 왜 훅이 필요한가

배치 정규화 계층을 넣었더니 모델의 수렴이 빨라지고 분류 정확도가 높아졌다고 하자. 이것이 **정말로 배치 정규화 때문인지** 말하려면 근거가 있어야 한다. 모델의 성능 변화에는 여러 원인이 얽혀 있기 때문이다.

- 순전파 과정에서 **각 계층 출력의 평균과 표준편차**를 직접 봐야 배치 정규화가 제대로 동작하고 있음을 확인할 수 있다.
- 역전파 과정에서 **기울기 값**을 직접 들여다봐야 기울기 소실이나 폭주를 막고 있음을 확인할 수 있다.

문제는 이 값들이 모델 안에서만 흐르고 밖으로 나오지 않는다는 점이다. 가장 쉽게 떠오르는 방법은 모델 클래스의 `forward()`에 `print()`를 끼워 넣는 것이다. 하지만 이 방법에는 세 가지 문제가 있다.

1. **번거롭다.** 보고 싶은 계층이 바뀔 때마다 클래스를 고쳐야 한다.
2. **위험하다.** 모델 코드를 건드리다 실수로 동작을 바꿀 수 있다. 디버깅하려다 디버깅할 대상을 만드는 셈이다.
3. **아예 불가능할 때가 있다.** 허깅페이스에서 내려받은 모델처럼 남이 만든 클래스는 고칠 수 없거나, 고쳐서도 안 된다.

**훅**(hook)은 이 세 가지를 한꺼번에 푼다. 훅은 파이토치가 제공하는 기능으로, 모델을 수정하지 않고 문제점을 파악하고 나아가 전달되는 데이터나 기울기 값까지 바꿀 수 있는 **모델 전용 디버거**다.

이름 그대로 모델의 특정 지점에 '갈고리'를 걸어 두는 것이라고 생각하면 된다. 데이터가 그 지점을 지날 때마다 걸어 둔 갈고리가 걸리고, 우리가 미리 정해 둔 함수가 실행된다.

## 2. 훅의 세 단계 — 정의, 등록, 제거

파이토치 훅은 늘 같은 세 단계로 쓴다.

```
콜백 함수 정의  →  훅 등록(핸들 보관)  →  사용  →  훅 제거
```

마지막 단계를 빠뜨리기 쉬운데, 뒤에서 보듯 빠뜨리면 실제로 문제가 생긴다.

### 2.1 콜백 함수 정의

먼저 텐서의 값이나 기울기를 확인하거나 수정할 **콜백 함수**를 정의한다. 콜백 함수의 서명(인자의 개수와 순서)은 **어떤 등록 메서드를 쓰느냐에 따라 정해져 있다.** 우리가 마음대로 정하는 것이 아니다.

예를 들어 순전파 과정에서 어떤 계층을 통과하는 입력과 출력을 살펴보려면 `모듈, 입력 텐서, 출력 텐서` 순서로 인자를 받도록 정의한다.

**[코드 1] 계층의 입력과 출력 데이터의 평균과 표준편차를 출력하는 훅 함수**

```python
# 데이터가 계층을 통과할 때 전후 데이터의 평균과 표준편차를 계산해 출력
#   module: 훅을 등록할 계층
#   inputs: 계층으로 입력된 텐서
#     여러 계층의 출력이 입력되는 경우를 고려한 튜플 형태
#   output: 계층이 출력하는 텐서
#   (register_forward_hook 메서드로 훅을 등록하는 경우)
def data_inspect_hook(module, inputs, output):
    # 계층 입력 데이터의 평균과 표준편차
    # 연결된 이전 계층이 하나뿐이므로 inputs[0]만 계산
    input_mean = inputs[0].mean().item()
    input_std = inputs[0].std().item()
    # 계층 출력 데이터의 평균과 표준편차
    output_mean = output.mean().item()
    output_std = output.std().item()
    # 계층 통과 전후의 평균과 표준편차 출력
    print(f' {input_mean:.2f}({input_std:.2f}) -> {output_mean:.2f}({output_std:.2f})')
```

여기서 `inputs`가 **튜플**이라는 점에 주의하자. 여러 계층의 출력이 한 계층으로 모여 들어오는 경우까지 고려한 형태다. 반면 `output`은 튜플이 아니라 텐서 하나다. 이 비대칭이 훅을 처음 쓸 때 가장 자주 걸려 넘어지는 지점이다.

> **콜백 함수는 클로저로 만들 수도 있다.** 계층 이름 같은 정보를 함께 담고 싶을 때 유용하다. 7.1절에서 다룬다.

### 2.2 훅 등록과 핸들 관리

정의한 콜백 함수는 **훅 등록 메서드**로 모듈이나 텐서에 등록한다. 등록 메서드는 **훅 핸들**을 반환하는데, 훅을 제거할 때 반드시 필요하므로 변수에 담아 둬야 한다.

**[표 1] 대표적인 훅 등록 메서드**

| | `register_forward_hook()` | `register_full_backward_hook()` | `register_hook()` |
|---|---|---|---|
| **구분** | 모듈 훅 | 모듈 훅 | 텐서 훅 |
| **실행** | 순전파, 계층 연산 후 | 역전파, 기울기 계산 후 최적화 이전 | 텐서의 기울기가 계산될 때마다 |
| **인자** | `module`, `inputs`, `output` | `module`, `grad_inputs`, `grad_outputs` | `grad` |
| **주요 용도** | 계층의 입력값과 출력값을 수집 | 기울기 값을 확인하거나 최적화 이전 수정 | 특정 텐서의 기울기 값을 수집하거나 실시간 수정 |

훅은 실행 조건과 동작 대상에 따라 **모듈 훅**과 **텐서 훅**으로 나뉜다. 여기서 모듈이란 합성곱 계층, 배치 정규화 계층 같은 모델의 부품뿐 아니라 `nn.Module`을 상속해 만든 **모델 객체 자체**도 포함한다. 모델에 훅을 걸면 모델 전체의 입출력을 볼 수 있다.

이 셋 말고도 상황에 따라 쓰는 메서드가 더 있다.

| 메서드 | 실행 시점 |
|---|---|
| `register_forward_pre_hook()` | 순전파, 계층 연산 **전** |
| `register_full_backward_pre_hook()` | 역전파, 해당 계층의 기울기 계산 **전** |

`register_forward_pre_hook()`은 계층에 들어가기 **직전**의 입력을 보거나 바꿀 때 쓴다. 입력을 가로채 정규화하거나, 잘못된 값이 들어오는지 감시하는 용도로 유용하다.

### 2.3 등록할 계층에 접근하기

훅을 등록하려면 먼저 그 계층 객체에 접근할 수 있어야 한다. 모델을 정의할 때 생성자에서 **속성 변수**로 만든 계층은 모델 객체의 속성으로 바로 접근하면 된다.

문제는 VGG 블록처럼 `nn.Sequential`에 계층 객체를 인자로 넘겨 만든 경우다. 이때는 이름이 없으므로 **순서 기준의 인덱싱**으로 접근한다.

`MiniVGGNetBN`([코드 8-3])의 첫 번째 배치 정규화 계층을 찾아보자. `torchinfo.summary()`의 출력([코드 8-4])에서 이 계층은 `BatchNorm2d: 3-2`로 표시된다. 이 계층은 `Sequential: 1-1`(= `model.features`) 안의 첫 번째 계층인 `Sequential: 2-1`(= 첫 번째 VGG 블록), 그 안의 두 번째 계층이다. 따라서 다음과 같이 접근한다.

**[코드 2] 모델의 첫 번째 배치 정규화 계층에 훅 등록**

```python
# 훅을 등록할 모델
model = MiniVGGNetBN()

# 훅을 추가할 계층: model.features의 첫 번째 VGG 블록의 두 번째 계층
target_layer = model.features[0][1]

# 훅 등록: register_forward_hook은 순전파에서 데이터가 target_layer를 통과할 때 실행
hook_handle = target_layer.register_forward_hook(data_inspect_hook)
```

인덱스를 손으로 세는 것이 번거롭다면 `model.named_modules()`로 이름과 함께 훑는 방법도 있다. 계층이 많은 모델에서는 이쪽이 훨씬 안전하다.

```python
for name, module in model.named_modules():
    if isinstance(module, nn.BatchNorm2d):
        print(name)        # features.0.1, features.0.4, features.1.1, ...
```

### 2.4 훅 제거 — 반드시 해야 한다

등록한 훅은 **직접 제거하지 않으면 사라지지 않는다.** 남아 있는 훅은 모델을 사용할 때마다 조건만 맞으면 자동으로 실행된다. 훅 핸들의 `remove()` 메서드로 제거한다.

**[코드 3] 등록한 훅 제거**

```python
# 훅 핸들의 remove() 메서드로 제거
hook_handle.remove()
```

제거를 빠뜨리면 무슨 일이 생길까? 두 가지다.

1. **느려지고 어지러워진다.** 디버깅용 `print()` 훅을 걸어 둔 채 학습을 시작하면 배치마다 출력이 쏟아진다.
2. **메모리가 샌다.** 이쪽이 훨씬 위험하다. 훅 안에서 출력 텐서를 `detach()` 없이 리스트나 딕셔너리에 모으면, 그 텐서에 딸린 **연산 그래프 전체**가 함께 붙잡힌다. 에포크가 돌수록 메모리가 쌓여 결국 메모리 부족 오류로 학습이 멈춘다.

```python
feature_maps.append(output)             # 위험: 연산 그래프까지 붙잡는다
feature_maps.append(output.detach())    # 안전: 값만 떼어 낸다
```

여러 계층에 훅을 걸었다면 핸들을 리스트에 모아 두고 한꺼번에 제거하는 것이 안전하다.

```python
handles = [layer.register_forward_hook(hook) for layer in layers]
...
for handle in handles:
    handle.remove()
```

## 3. 순전파 훅으로 배치 정규화 관찰하기

이제 [코드 1]과 [코드 2]를 실제로 돌려 보자. 배치 정규화는 학습 모드와 평가 모드에서 다르게 동작하므로, 두 모드에서 각각 확인한다.

**[코드 4] 모드에 따른 배치 정규화 훅 실행 결과**

```python
# 데이터가 target_layer(첫 번째 배치 정규화 계층)를 지날 때
# 배치 정규화 전후의 평균과 표준편차를 출력하는 data_inspect_hook() 함수가 자동 실행
print('배치 정규화 전 평균(표준편차) --> 배치 정규화 후 평균(표준편차)')
print('학습 모드')
model.train()
for i, (inputs, targets) in enumerate(train_loader):
    # 5개의 배치 입력에 대해서 확인
    if i == 5:
        break
    output = model(inputs)              # 순전파 발생 -> 훅 실행

# 훅은 모드와 무관하게 작동하므로 평가 모드에서도 전후의 평균과 표준편차를 출력하지만
# 배치 정규화는 학습 모드와 평가 모드에서 다른 방식으로 동작하므로 출력 결과는 다름
print('평가 모드')
model.eval()
for i, (inputs, targets) in enumerate(train_loader):
    output = model(inputs)
    break
```

```
배치 정규화 전 평균(표준편차) --> 배치 정규화 후 평균(표준편차)
학습 모드
 0.01(0.28) -> -0.00(1.00)
 0.01(0.28) -> 0.00(1.00)
 0.00(0.29) -> 0.00(1.00)
 0.01(0.28) -> 0.00(1.00)
 0.01(0.30) -> -0.00(1.00)
평가 모드
 0.01(0.28) -> 0.01(0.35)
```

**학습 모드**에서는 입력의 분포가 배치마다 조금씩 다른데도(표준편차 0.28~0.30) 출력은 언제나 평균 0, 표준편차 1로 맞춰진다. 배치 정규화가 의도한 대로 계층의 출력을 균일하게 가다듬고 있다.

**평가 모드**에서는 표준편차가 1이 아니라 0.35다. 평가 모드의 배치 정규화는 배치별 통계 대신 **학습 중 누적해 둔 이동평균과 이동분산**을 쓰기 때문이다. 지금 이 모델은 아직 학습을 거치지 않아 이동 통계가 초깃값(평균 0, 분산 1) 근처에 머물러 있고, 그래서 입력의 분포(표준편차 0.28)가 거의 그대로 통과한다.

**훅 자체는 모드와 무관하게 작동한다.** 모드에 따라 달라지는 것은 배치 정규화 계층의 동작이지 훅이 아니다. 이 구분을 놓치면 출력을 잘못 읽게 된다.

## 4. 역전파 훅으로 기울기 관찰하기

### 4.1 모듈 훅과 텐서 훅은 서로 다른 기울기를 본다

`register_full_backward_hook()`으로 등록한 콜백과 `register_hook()`으로 등록한 콜백은 **둘 다 역전파 과정에서 계산된 기울기를 받는다.** 그래서 같은 값이라고 오해하기 쉬운데, 이 둘은 명확히 다르다.

역전파에서 어떤 계층에 '책임'이 전달되면 두 가지 일이 벌어진다.

**(가) 계층의 파라미터가 책임을 나눠 진다.** 파라미터의 값을 조금 바꿔 봤을 때 손실이 크게 줄어드는 파라미터일수록 더 큰 책임을 진다. 즉 파라미터 값에 대한 손실의 기울기를 자동 미분으로 계산한다. 이 기울기는 파라미터 텐서마다 계산되어 텐서의 `grad` 속성에 저장되며, **텐서 훅**(`register_hook()`)으로 확인한다.

**(나) 책임의 일부를 앞 계층으로 넘긴다.** 순전파에서 앞 계층이 전달한 값을 기준으로, 그 값이 커질 때 손실이 얼마나 커지는지를 계산한다. 이 값은 **계층 사이에 오가는 오차 신호**이며, **모듈 훅**(`register_full_backward_hook()`)으로 확인한다.

둘은 밀접하게 연결되어 있다. 뒤 계층에서 전달된 오차 신호가 클수록 각 파라미터의 기울기도 커진다. 그러나 **가리키는 대상이 다르다.** 하나는 '이 파라미터를 얼마나 바꿔야 하는가'이고, 다른 하나는 '앞 계층에 얼마만큼의 책임을 넘길 것인가'이다.

> **이름에 속지 말자.** 모듈 훅의 인자 이름은 계층의 배치 순서를 따라 붙었다. 역전파에서 **뒤 계층에서 전달된** 기울기 신호가 `grad_outputs`, **앞 계층으로 전달할** 기울기 신호가 `grad_inputs`다. 역전파의 진행 방향과 이름이 반대로 느껴져 오해하기 쉽다.

### 4.2 기울기 신호를 출력하는 훅

**[코드 5] 역전파로 전달된 기울기 신호의 정보를 출력하는 훅 함수**

```python
# 역전파에서 뒤 계층에서 전달된 기울기 신호(grad_outputs)의 최댓값 및 노름을 출력
# module: 훅을 등록할 계층
# grad_inputs: 앞 계층으로 전달할 기울기 신호(여러 계층으로 전달할 경우를 고려한 튜플 형태)
# grad_outputs: 뒤 계층에서 전달된 기울기 신호(여러 계층에서 전달될 경우를 고려한 튜플 형태)
#               (register_full_backward_hook 메서드로 훅을 등록하는 경우)
# 훅 등록 메서드에 따라 사용하지 않는 인자도 자리를 채워야 함(module과 grad_inputs)
def gradient_hook(module, grad_inputs, grad_outputs):
    # 절댓값의 최댓값: 기울기 소실 또는 폭주 확인
    grad_max = grad_outputs[0].abs().max().item()
    # 노름: 벡터 또는 텐서의 크기 지표(텐서의 norm() 메서드 사용)
    grad_norm = grad_outputs[0].norm().item()
    print(f' 최댓값: {grad_max:.6f}, 노름: {grad_norm:.6f}')
```

두 지표를 함께 보는 이유가 있다. **노름**은 기울기 신호의 전반적인 강도를 알려 주고, **절댓값의 최댓값**은 기울기 폭주 같은 국소적인 이상 징후를 잡아낸다. 노름이 멀쩡해도 특정 요소 하나가 튀면 학습이 흔들릴 수 있다.

다만 특정 배치, 특정 계층의 값 하나로 학습 안정성을 판단할 수는 없다. **앞뒤 계층의 값과 함께, 여러 배치와 에포크에 걸쳐 비교해야** 의미가 있다.

> **텐서의 노름**
> 수학에서 벡터의 노름은 원점으로부터의 거리와 비슷한 값으로, 유클리드 공간에서 노름(L2 norm)은 거리의 정의와 같다. 딥러닝에서는 텐서 요솟값들의 절대적인 크기로 **텐서의 전반적인 강도**를 알려 주는 지표로 주로 사용한다. 파이토치에서는 텐서의 `norm()` 메서드나 `torch.linalg.norm()` 함수로 계산한다.

### 4.3 계층 위치에 따른 기울기의 변화

역전파 훅을 출력층에서 떨어진 거리에 따라 여러 계층에 걸면, 출력층에서 멀어질수록 기울기 신호가 어떻게 변하는지 그 경향을 볼 수 있다.

**[코드 6] 훅을 통한 기울기 신호 검사**

```python
# 검사 대상 모델: MiniVGGNetBN
model_vggbn = MiniVGGNetBN()
# 훅을 등록할 계층
conv_layers = []
# features[i][j]: (i + 1)번째 VGG 블록의 (j + 1)번째 계층
# 계층은 Conv2d(0) -> BatchNorm2d -> ReLU -> Conv2d(3) -> BatchNorm2d -> ReLU -> MaxPool2d 순서
conv_layers.append(model_vggbn.features[0][0])  # 첫 번째 블록의 첫 번째 합성곱
conv_layers.append(model_vggbn.features[1][0])  # 두 번째 블록의 첫 번째 합성곱(3번째)
conv_layers.append(model_vggbn.features[2][3])  # 세 번째 블록의 두 번째 합성곱(마지막)

# 역전파에서 계층의 기울기가 계산될 때 호출되는 훅 등록
# 리스트에 모으면 훅을 일괄 제거할 수 있음
handles = []
for layer in conv_layers:
    handle = layer.register_full_backward_hook(gradient_hook)
    handles.append(handle)

# 첫 번째 배치의 역전파만 확인(최적화 없이 backward()만으로 역전파 진행)
inputs, targets = next(iter(train_loader))
criterion = nn.CrossEntropyLoss()
print('모델 MiniVGGNetBN')
model_vggbn.train()
output = model_vggbn(inputs)
loss = criterion(output, targets)
loss.backward()

# 리스트에 저장해 둔 훅 핸들을 사용해 훅 일괄 제거
for handle in handles:
    handle.remove()
```

**출력 순서에 주의하자.** 역전파에 반응하는 훅이므로 **출력층에 가까운 계층의 훅이 먼저 실행된다.** 가장 먼저 출력된 값이 마지막 합성곱 계층의 것이고, 마지막 출력이 첫 번째 합성곱 계층의 것이다.

> **경고 메시지가 나와도 괜찮다.** [코드 6]을 실행하면 일부 훅에 출력 기울기만 전달된다는 경고가 나온다. `register_full_backward_hook()`으로 등록한 모듈은 콜백을 호출할 때 `grad_inputs`와 `grad_outputs`를 함께 넘기는데, `requires_grad=False`인 이미지 텐서를 입력받는 **첫 번째 합성곱 계층은 `grad_inputs`에 전달할 기울기가 없다.** 이때 해당 인자는 `None`이 되고 경고가 나온다. 예제처럼 그 값을 쓰지 않는다면 무시해도 된다.

이 훅을 8장의 세 모델에 각각 걸어 측정한 결과가 본문 [표 8-4]다.

**[표 2] 합성곱 계층의 위치별 손실 기울기 노름의 변화**

| 합성곱 계층 순서 | `MiniAlexNet` | `MiniVGGNet` | `MiniVGGNetBN` |
|---|---|---|---|
| 1 | 0.009919 | 0.000267 | **0.282153** |
| 3 | – | 0.001338 | 0.074192 |
| 마지막 | 0.021823 | 0.020678 | 0.056166 |

- **배치 정규화가 없는 모델의 기울기 소실**: `MiniVGGNet`은 앞 계층으로 갈수록 노름이 크게 줄어든다(0.0207 → 0.0013 → 0.0003). 계층이 조금만 더 늘어나도 0에 수렴할 것으로 보인다.
- **계층이 많을수록 심해진다**: 합성곱 계층이 둘뿐인 `MiniAlexNet`도 입력에 가까운 계층의 노름이 더 작지만, `MiniVGGNet`에 비하면 소실 경향이 훨씬 덜하다.
- **배치 정규화의 기울기 보강**: `MiniVGGNetBN`은 오히려 **첫 번째 합성곱 계층의 노름이 가장 크다.** 기울기 소실의 징후를 전혀 찾을 수 없다.

## 5. 사례 연구 — 8-3절의 배치 정규화 부작용 실험

8-3절은 "배치 정규화 계층이 지나치게 많아지면 배치 정규화 자체가 함정이 된다"는 것을 [표 8-5], [표 8-6]과 [그림 8-4]로 보인다. 본문은 지면 때문에 결과만 싣고 실험 코드는 생략했다. 여기서 그 실험을 처음부터 따라가 본다. **훅을 배우는 자료로서도 좋은 사례다.** 마지막에 같은 실험을 훅으로 다시 구현해 두 방법의 차이를 짚는다.

### 5.1 무엇을 확인하려는 실험인가

어떤 프로그램이든 같은 입력에는 같은 결과가 나와야 한다. 그렇다면 **거의 같은** 입력에는 거의 같은 결과가 나와야 하지 않을까? 이 실험은 그 상식이 깊은 신경망에서 깨지는 것을 보인다.

설계는 세 부분이다.

1. **모델** — 합성곱과 배치 정규화만 반복해 쌓은 단순한 모델을 깊이만 바꿔 가며 만든다.
2. **입력** — 값이 똑같은 텐서 한 쌍과, 소수점 다섯째 자리 수준에서만 다른 텐서 한 쌍을 준비한다.
3. **측정** — 출력이 얼마나 벌어지는지(순전파), 계층별 기울기의 방향이 얼마나 어긋나는지(역전파)를 잰다.

### 5.2 실험용 모델

성능이 좋은 모델을 만드는 것이 목적이 아니다. **배치 정규화 계층의 개수만 변수로 두기 위해** 최대한 단순하게 만든다. 풀링도 분류기도 없다.

**[코드 7] 배치 정규화의 부작용을 실험하기 위한 모델**

```python
# 배치 정규화를 num_blocks회 반복하는 단순한 합성곱 모델
#   배치 정규화의 부작용을 확인하는 것이 목적이며, 성능이 좋은 모델을 만드는 것이 아님
class StackedConvBN(nn.Module):
    def __init__(self, num_blocks, channels=16):
        super().__init__()
        # 첫 합성곱으로 채널 수를 channels로 맞춤
        layers = [
            nn.Conv2d(3, channels, 3, padding=1, bias=False),
            nn.BatchNorm2d(channels),
            nn.ReLU(),
        ]
        # 이후 num_blocks - 1회 반복해 동일 채널 합성곱 + 배치 정규화 블록 추가
        for _ in range(num_blocks - 1):
            layers.append(nn.Conv2d(channels, channels, 3, padding=1, bias=False))
            layers.append(nn.BatchNorm2d(channels))
            layers.append(nn.ReLU())
        self.features = nn.Sequential(*layers)

    def forward(self, x):
        return self.features(x)
```

`bias=False`인 이유는 8-2절에서 설명한 것과 같다. 뒤따르는 배치 정규화의 위치 파라미터(β)가 편향의 역할을 대신한다.

### 5.3 순전파 — 출력이 얼마나 벌어지는가

**[코드 8] 두 입력에 대한 출력의 유클리드 거리와 코사인 유사도**

```python
@torch.no_grad()
def measure_similarity(model, x_a, x_b):
    model.train()
    # 두 입력 텐서를 묶어서 마치 하나의 배치인 것처럼 모델에 입력
    #   배치 정규화는 배치 단위 통계를 사용해 정규화하므로,
    #   학습에서 배치마다 입력이 달라지는 상황과 같은 조건이 됨
    outputs = model(torch.cat([x_a, x_b], dim=0))
    y_a = outputs[0].flatten()
    y_b = outputs[1].flatten()
    # 거리: 두 출력 텐서의 노름(유클리드 거리)
    dist = (y_a - y_b).norm().item()
    # 유사도: 코사인 유사도
    cos = F.cosine_similarity(y_a.unsqueeze(0), y_b.unsqueeze(0)).item()
    return dist, cos
```

**여기서 가장 중요한 줄은 `torch.cat([x_a, x_b], dim=0)`이다.** 두 입력을 **한 배치에 함께 넣는다.** 왜 따로 넣지 않을까?

배치 정규화는 배치 전체의 통계로 정규화한다. 두 입력을 각각 크기 1인 배치로 넣으면 서로 다른 통계가 쓰여, 우리가 보려는 것(입력의 미세한 차이가 어떻게 증폭되는가)이 아니라 **통계 자체가 달라진 효과**를 보게 된다. 한 배치에 넣으면 두 샘플이 같은 통계를 공유하므로, 출력의 차이는 오직 입력의 차이가 계층을 지나며 번진 결과다. 그리고 이것이 **학습 중 배치마다 입력이 바뀌는 실제 상황과 같은 조건**이다.

`model.train()`을 부른 것도 같은 이유다. 평가 모드였다면 이동 통계를 쓰므로 배치 구성과 무관해져 실험 자체가 성립하지 않는다.

입력은 다음과 같이 만든다.

```python
test_input = torch.randn(1, 3, 32, 32)
same_input = test_input.clone()                          # 값이 같은 텐서
similar_input = test_input + 1e-5 * torch.randn_like(test_input)   # 거의 같은 텐서
```

`1e-5`는 소수점 **다섯째** 자리 수준의 섭동이다. 사람 눈으로는 물론이고 화면에 출력해도 구분하기 어렵다.

결과는 본문 [표 8-5], [표 8-6]과 같다. 값이 같은 두 텐서는 어느 깊이에서든 거리 0, 유사도 1이다. 그런데 거의 같은 두 텐서에서는 깊이가 늘수록 거리가 0.007 → 3.84 → 100으로 폭발하고, 96 합성곱 모델은 코사인 유사도마저 0.39로 떨어진다. **크기뿐 아니라 방향까지 어긋난 것이다.**

### 5.4 역전파 — 기울기의 방향이 얼마나 어긋나는가

순전파의 차이보다 심각한 것은 역전파다. 기울기의 **방향**이 달라지면 모델이 배치마다 서로 다른 곳으로 끌려간다.

**[코드 9] 합성곱 계층별 기울기의 코사인 유사도**

```python
def layer_grad_cosines(model, x_a, x_b):
    conv_layers = [m for m in model.modules() if isinstance(m, nn.Conv2d)]

    def grads_for_input(x):
        for layer in conv_layers:
            layer.weight.grad = None        # 이전 결과가 누적되지 않도록 초기화
        out = model(x)
        # 전역 평균 풀링 후 합을 손실로 삼아 합성곱 기울기를 구함
        loss = F.adaptive_avg_pool2d(out, 1).flatten().sum()
        loss.backward()
        return [layer.weight.grad.flatten().clone() for layer in conv_layers]

    model.train()
    grads_a = grads_for_input(x_a)
    grads_b = grads_for_input(x_b)
    # 앞부분이 입력에 가까운 계층, 뒷부분이 출력에 가까운 계층
    return [
        F.cosine_similarity(ga.unsqueeze(0), gb.unsqueeze(0)).item()
        for ga, gb in zip(grads_a, grads_b)
    ]
```

짚어 둘 것이 세 가지다.

**`model.modules()`로 계층을 찾는다.** 2.3절에서 인덱싱으로 계층에 접근했는데, 계층이 96개나 되면 그럴 수 없다. `modules()`는 모델 안의 모든 하위 모듈을 재귀적으로 훑어 준다. 여기에 `isinstance()`로 거르면 원하는 종류의 계층만 순서대로 모을 수 있다. **훅을 여러 계층에 걸 때 늘 쓰게 되는 패턴이다.**

**손실 함수가 특이하다.** 이 모델에는 분류기가 없어 정답과 비교할 수 없다. 그래서 출력 특징 지도를 전역 평균 풀링으로 눌러 모두 더한 값을 손실로 삼는다. 진짜 학습이 목적이 아니라 **역전파를 한 번 발생시켜 기울기를 만드는 것**이 목적이므로 이것으로 충분하다.

**`layer.weight.grad = None`으로 초기화한다.** 파이토치는 `backward()`를 부를 때마다 기울기를 `.grad`에 **누적**한다. 두 입력에 대해 연달아 역전파하면서 초기화하지 않으면 두 결과가 더해져 버린다.

### 5.5 한 번의 실행으로 결론 내지 말 것 — 시드 민감도

**이 실험에는 함정이 있다.** 학습을 거치지 않은 모델에 곧바로 역전파를 한 번 일으켜 재므로,
**무작위 초기 가중치가 곧 실험 조건이다.** 시드를 바꾸면 결과가 얼마나 달라질까? 예제와 같은
방식으로 시드만 바꿔 일곱 번 돌려 봤다.

**[표 3] 96 합성곱 모델의 계층별 코사인 유사도 — 시드에 따른 변화**

|---|---|---|---|---|
| 42 | 0.063 | 0.683 | −0.134 | 44개 (45.8%) |
| 0 | −0.008 | 0.907 | −0.175 | **72개 (75.0%)** |
| 1 | 0.032 | 0.806 | −0.128 | 60개 (62.5%) |
| 7 | 0.115 | 0.761 | −0.074 | **12개 (12.5%)** |
| 123 | 0.065 | 0.822 | −0.149 | 31개 (32.3%) |
| 2024 | 0.028 | 0.375 | −0.093 | 30개 (31.2%) |
| 31337 | 0.067 | 0.696 | −0.104 | 26개 (27.1%) |

**0 미만인 계층의 비율이 12.5%에서 75.0%까지 요동친다.** 최댓값도 0.375에서 0.907까지 벌어진다.
시드 하나의 결과만 보고 "절반이 넘는 계층에서 방향이 뒤집힌다"처럼 단정하면, 다른 시드로
재현한 독자와 이야기가 어긋난다.

**그렇다면 무엇이 견고한가.** 같은 일곱 시드에서 모델별 평균을 견주면 답이 나온다.

흔들리지 않는다.** 96 합성곱 모델의 평균은 언제나 0 근처이고, 잔차 학습 모델은 언제나
1에 붙어 있다. 잔차 모델은 **평균뿐 아니라 최저값까지** 0.999를 넘는다는 점이 특히 인상적이다.

> **훅으로 잰 값을 읽을 때의 원칙**
> 훅은 모델 내부의 값을 그대로 보여 주지만, 그 값이 **무엇에 의해 정해지는지**는 알려 주지 않는다.
> 학습 전 모델을 재는 실험이라면 초기 가중치가, 배치 하나만 재는 실험이라면 그 배치의 구성이
> 결과를 좌우한다. **여러 시드와 여러 배치에서 공통으로 나타나는 것만 결론으로 삼자.**
> 4.2절에서 "특정 배치, 특정 계층의 값 하나로 학습 안정성을 판단할 수는 없다"고 한 것과 같은 이야기다.

### 5.6 같은 실험을 훅으로 구현하면

[코드 9]는 **훅을 쓰지 않는다.** `backward()`가 끝난 뒤 `.grad`에 쌓인 값을 읽을 뿐이다. 이 실험처럼 역전파가 끝난 뒤 한 번에 값을 거두면 되는 경우에는 이 방법이 가장 간단하다.

그렇다면 훅은 언제 필요할까? 같은 일을 텐서 훅으로 해 보면 차이가 드러난다.

**[코드 10] 텐서 훅으로 가중치 기울기 모으기**

```python
def collect_weight_grads_with_hook(model, x):
    conv_layers = [m for m in model.modules() if isinstance(m, nn.Conv2d)]
    grads = {}

    def make_hook(index):
        # register_hook 서명(grad)에 맞는 훅 함수를 반환
        def hook(grad):
            grads[index] = grad.flatten().clone()
        return hook

    # 각 합성곱 계층의 가중치 텐서에 텐서 훅 등록
    handles = [layer.weight.register_hook(make_hook(i))
               for i, layer in enumerate(conv_layers)]

    model.train()
    model.zero_grad()
    out = model(x)
    loss = F.adaptive_avg_pool2d(out, 1).flatten().sum()
    loss.backward()

    for handle in handles:
        handle.remove()
    # 등록 순서(입력 -> 출력)대로 정렬해 반환
    return [grads[i] for i in range(len(conv_layers))]
```

두 방법은 같은 값을 준다. 하지만 **보는 시점이 다르다.**

| | `.grad` 직접 읽기 | 텐서 훅 |
|---|---|---|
| 보는 시점 | 역전파가 **끝난 뒤** | 기울기가 **계산되는 순간** |
| 보는 값 | `.grad`에 **누적된** 값 | 이번에 계산된 값 하나 |
| 값 수정 | 불가(이미 끝났다) | 가능(반환값이 `.grad`에 쌓인다) |
| 코드 | 짧다 | 등록과 제거가 필요하다 |

**두 번째 줄이 핵심이다.** 기울기 누적(gradient accumulation)을 쓰거나 한 파라미터가 여러 경로에서 기울기를 받는 모델에서는, `.grad`를 읽으면 **합쳐진 값**만 보인다. 훅은 각 기여를 따로 볼 수 있다. 6.2절의 기울기 클리핑처럼 **역전파 도중에 값을 바꿔야 할 때**도 훅만 가능하다.

**이 실험에서는 `.grad` 쪽이 더 나은 선택이다.** 훅이 언제나 정답은 아니라는 것도 함께 기억해 두자.

### 5.7 잔차 학습 모델로 같은 실험 반복하기

8-3절은 같은 실험을 잔차 학습 모델로 반복해 [그림 8-6]을 얻는다. 모델만 바꾸면 된다.

```python
class StackedResBlock(nn.Module):
    def __init__(self, num_convs, channels=16):
        super().__init__()
        layers = [
            nn.Conv2d(3, channels, 3, padding=1, bias=False),
            nn.BatchNorm2d(channels),
            nn.ReLU(),
        ]
        # 각 잔차 블록이 합성곱 2개를 포함하므로 잔차 블록은 절반을 사용
        num_res_blocks = (num_convs - 1) // 2
        for _ in range(num_res_blocks):
            layers.append(ResidualBlock(channels, channels))
        self.features = nn.Sequential(*layers)

    def forward(self, x):
        return self.features(x)
```

결과는 극적이다. 배치 정규화만 쌓은 96 합성곱 모델은 기울기 방향이 무너졌는데, **같은 깊이의 잔차 학습 모델은 모든 계층에서 코사인 유사도가 1에 가깝게 유지된다.** 384개를 쌓아도 마찬가지다. 잔차 블록의 수에 비례해 배치 정규화 계층도 함께 늘어났는데도 그렇다.

> **주의 — 합성곱 계층 수가 하나 모자란다.** 위 코드에서 실제 합성곱 계층 수는 `1 + 2 x ((num_convs - 1) // 2)`다. `num_convs`가 짝수면 지정한 값보다 하나 적다(12 → 11, 96 → 95, 384 → 383). `StackedConvBN(n)`은 정확히 `n`개를 만들므로 두 실험의 깊이가 하나씩 어긋난다. 유사도가 1에 가깝게 유지된다는 결론은 바뀌지 않지만, 직접 실험할 때는 `num_res_blocks = num_convs // 2`로 고치거나 홀수를 지정하자.

### 5.8 이 실험이 남기는 것

훅을 배우는 관점에서 이 실험은 세 가지를 보여 준다.

1. **`model.modules()` + `isinstance()`** — 계층이 많은 모델에서 원하는 계층만 골라내는 표준 패턴
2. **역전파를 일부러 한 번 일으키는 법** — 진짜 학습 없이도 기울기를 관찰할 수 있다
3. **훅이 필요한 경우와 필요 없는 경우의 구분** — 끝난 뒤 값만 보면 될 때는 `.grad`, 도중에 개입하거나 각 기여를 따로 봐야 할 때는 훅

## 6. 훅으로 값을 바꾸기

지금까지는 훅으로 값을 **보기만** 했다. 그런데 훅의 정의에는 "전달되는 데이터나 기울기 값도 바꿀 수 있는"이 들어 있다. 훅은 관찰 도구이면서 **개입 도구**이기도 하다.

### 6.1 순전파 훅으로 출력 바꾸기

`register_forward_hook()`으로 등록한 콜백이 **값을 반환하면, 그 값이 계층의 출력을 대체한다.** 아무것도 반환하지 않으면(`None`) 원래 출력이 그대로 흘러간다. 지금까지의 예제가 값을 바꾸지 않은 이유다.

```python
def clamp_hook(module, inputs, output):
    # 출력을 [-0.5, 0.5] 범위로 잘라 다음 계층으로 흘려보낸다
    return output.clamp(-0.5, 0.5)
```

**자를 범위를 정할 때는 그 계층의 실제 출력 범위를 먼저 봐야 한다.** 배치 정규화를 갓 통과한 값은 대부분 −3에서 3 사이에 들어오므로, `clamp(-3, 3)`으로는 아무 값도 잘리지 않아 훅을 걸어도 결과가 그대로다. 훅이 동작하지 않는 것처럼 보이면 조건 자체를 의심해 보자. 연습 문제 1의 방법으로 범위를 먼저 재 보면 확실하다.

특정 계층의 출력을 강제로 0으로 만들어 **그 계층이 정말 필요한지 확인하는** 용도로도 쓴다. 계층을 지우고 다시 학습할 필요 없이, 훅 하나로 '없는 셈 치고' 돌려 보는 것이다. 연습 문제 5에서 다룬다.

### 6.2 텐서 훅으로 기울기 바꾸기 — 기울기 클리핑 직접 만들기

6장에서 다룬 **기울기 클리핑**을 텐서 훅으로 직접 구현해 보면 훅의 개입 능력을 실감할 수 있다.

```python
def make_clip_grad_hook(max_norm):
    def hook(grad):
        # 기울기의 노름이 max_norm을 넘으면 방향은 두고 크기만 줄인다
        norm = grad.norm()
        if norm > max_norm:
            return grad * (max_norm / norm)
        return grad              # None을 반환해도 원래 기울기가 유지된다
    return hook


handles = [p.register_hook(make_clip_grad_hook(1.0))
           for p in model.parameters()]
```

기준값을 인자로 받도록 클로저로 만들었다(7.1절 패턴). **기준값을 정하려면 그 모델의 기울기가 실제로 얼마나 큰지 먼저 알아야 한다.** `MiniVGGNet`에 배치 하나를 흘려 보면 가장 큰 파라미터의 기울기 노름이 0.09 남짓이라, 기준값 1.0으로는 **한 번도 걸리지 않는다.** 6.1절의 `clamp`와 같은 함정이다.

파이토치가 제공하는 `torch.nn.utils.clip_grad_norm_()`은 **역전파가 끝난 뒤** 모든 파라미터의 기울기를 모아 한꺼번에 자른다. 반면 위 훅은 **각 텐서의 기울기가 계산되는 순간** 개입한다. 둘은 계산 결과가 다르므로(전자는 전체 노름 기준, 후자는 텐서별 노름 기준) 바꿔 쓸 수 있는 것은 아니다. 다만 "역전파 도중에 끼어들 수 있다"는 점은 훅만의 능력이다.

### 6.3 개입할 때의 주의

값을 바꾸는 훅은 강력한 만큼 위험하다.

- **모델의 동작이 코드에 드러나지 않는다.** 모델 클래스만 읽어서는 왜 이런 결과가 나오는지 알 수 없다. 훅으로 개입했다면 반드시 기록을 남기자.
- **제자리 연산과 충돌할 수 있다.** 출력을 `output.clamp_(-3, 3)`처럼 제자리에서 바꾸면 자동 미분이 필요한 값을 덮어써 역전파에서 오류가 난다. **새 텐서를 반환하는 형태**를 쓰자.
- **훅이 여러 개면 순서가 중요하다.** 같은 지점에 등록한 훅은 등록한 순서대로 실행되고, 앞 훅이 바꾼 값이 뒤 훅에 전달된다.

## 7. 실전 패턴

### 7.1 클로저로 이름표 붙이기

계층 여러 개의 출력을 한꺼번에 모을 때, 콜백 함수만으로는 **지금 어느 계층에서 불린 것인지** 알기 어렵다. 이때 **정해진 서명의 훅 함수를 반환하는 클로저**를 만들면 계층 이름 같은 정보를 함께 담을 수 있다.

**[코드 11] 클로저로 만든 훅**

```python
feature_maps = {}                       # 계층 이름 -> 출력 특징 지도


def make_capture_hook(name):
    # register_forward_hook 서명(module, inputs, output)에 맞는 훅 함수를 반환
    def hook(module, inputs, output):
        feature_maps[name] = output.detach()
    return hook


model = MiniVGGNetBN()
# 첫 번째, 세 번째, 마지막(여섯 번째) 합성곱 계층에 클로저 훅을 등록
target_layers = {
    '첫 번째 합성곱': model.features[0][0],
    '세 번째 합성곱': model.features[1][0],
    '마지막 합성곱': model.features[2][3],
}
handles = [layer.register_forward_hook(make_capture_hook(name))
           for name, layer in target_layers.items()]

# 배치 하나를 통과시켜 특징 지도를 수집한 뒤 훅을 정리한다
inputs, _ = next(iter(train_loader))
model.eval()
with torch.no_grad():
    model(inputs)
for handle in handles:
    handle.remove()

for name, fmap in feature_maps.items():
    print(f'{name}: {tuple(fmap.shape)}')   # (배치, 채널, 높이, 너비)
```

`output.detach()`를 쓴 것에 주목하자. 2.4절에서 설명한 메모리 누수를 막는 습관이다.

### 7.2 특징 지도 들여다보기

훅으로 데이터를 관찰하는 가장 대표적인 쓰임새는 **합성곱 계층이 출력하는 특징 지도**를 계층별로 확인하는 것이다. 5장에서 필터가 경계나 질감을 잡아낸다고 배웠는데, 훅을 쓰면 그것을 눈으로 볼 수 있다.

```python
sample_index = 0                        # 배치에서 살펴볼 샘플 하나 선택
for name, fmap in feature_maps.items():
    # fmap[sample_index]: (C, H, W) - 앞 8개 채널만 골라 시각화
    viz.plot_feature_map(
        fmap[sample_index][:8], title=f'{name} 계층의 특징 지도(앞 8개 채널)',
    )
```

입력층에 가까운 계층일수록 경계나 색 덩어리처럼 **알아볼 수 있는** 무늬가 보이고, 출력층에 가까울수록 해상도가 낮아지고 사람 눈으로는 해석하기 어려운 추상적인 패턴이 된다. 5장에서 설명한 저수준 특징에서 고수준 특징으로의 이행을 직접 확인하는 셈이다.

### 7.3 자주 저지르는 실수

| 실수 | 증상 | 해결 |
|---|---|---|
| 훅을 제거하지 않음 | 학습이 느려지고 출력이 쏟아짐 | 핸들을 모아 `remove()` |
| `detach()` 없이 텐서 수집 | 에포크가 돌수록 메모리 증가, 결국 메모리 부족 | `output.detach()` |
| `inputs`를 텐서로 착각 | `AttributeError` 또는 엉뚱한 값 | `inputs[0]`으로 꺼내 쓴다 |
| 제자리 연산으로 값 수정 | 역전파에서 오류 | 새 텐서를 반환 |
| 평가 모드에서 배치 정규화 결과를 학습 모드와 같다고 가정 | 해석 오류 | 모드를 명시하고 따로 관찰 |
| `register_backward_hook()` 사용 | 값이 부정확하거나 경고 | `register_full_backward_hook()`을 쓴다 |

마지막 항목은 특히 주의하자. 이름이 비슷한 `register_backward_hook()`은 오래된 메서드이며 복잡한 모듈에서 잘못된 값을 줄 수 있어 **사용이 권장되지 않는다.**

---

## 8. 훅은 어디에 쓰이나

훅은 디버깅 도구에 머물지 않는다. 여러 고급 기법의 토대다.

- **Grad-CAM**: 모델이 이미지의 어느 부분을 보고 분류했는지 히트맵으로 보여 주는 기법이다. 마지막 합성곱 계층의 **특징 지도**(순전파 훅)와 그 계층으로 흘러든 **기울기**(역전파 훅)를 곱해 만든다. 이 글에서 배운 두 훅을 그대로 쓴다. 설명 가능한 인공지능(XAI)의 대표 기법이다.
- **중간 특징 추출**: 사전 학습 모델의 중간 계층 출력을 꺼내 다른 모델의 입력으로 쓴다. 8-4절의 전이 학습을 더 유연하게 확장하는 방법이다.
- **기울기 감시와 조정**: 학습이 불안정할 때 어느 계층에서 기울기가 터지는지 찾고, 필요하면 그 자리에서 조정한다.
- **모델 경량화**: 양자화나 프루닝에서 계층별 활성값의 분포를 수집해 어느 계층을 얼마나 줄일지 정한다.

## 연습 문제

**1.** 콜백 함수 `data_inspect_hook()`을 수정해 `MiniVGGNetBN` 모델에서 각 계층 출력 데이터의 최댓값과 최솟값을 출력해 보자. 그리고 출력에 가까운 계층일수록 이 값의 범위가 어떻게 변하는지 관찰해 보자.

**2.** CIFAR-10 샘플 하나에 해당하는 입력 텐서를 무작위 값으로 만들고 순전파와 역전파를 1회 실행하면서, `MiniVGGNetBN` 모델의 모든 합성곱 계층별 **가중치 기울기의 평균**을 출력해 보자.

> 힌트: 계층 사이를 오가는 오차 신호가 아니라 파라미터의 기울기를 봐야 한다. [표 1]에서 어느 훅을 써야 할지 골라 보자.

**3.** `register_forward_pre_hook()`으로 첫 번째 합성곱 계층에 훅을 걸어, 계층에 **들어가기 직전**의 입력 텐서의 형태와 값 범위를 출력해 보자. `register_forward_hook()`으로 같은 계층을 관찰했을 때와 무엇이 다른지 설명해 보자.

**4.** [도전 문제] 훅을 사용해 데이터를 관찰하는 대표적인 예제는 합성곱 계층이 출력하는 특징 지도를 계층별로 확인해 보는 것이다. `MiniVGGNetBN` 모델의 첫 번째, 세 번째, 마지막 합성곱 계층이 출력하는 특징 지도 중 각각 여덟 개씩 골라 이미지 파일로 저장해 보고, 특징 지도가 나타내는 바를 설명해 보자.

**5.** [도전 문제] 6.1절을 참고해 `MiniVGGNetBN`의 **마지막 VGG 블록 전체의 출력을 0으로 만드는** 훅을 등록한 뒤 평가 데이터셋의 분류 정확도를 측정해 보자. 훅을 등록하지 않았을 때와 비교하고, 그 차이가 무엇을 뜻하는지 설명해 보자.

**6.** [도전 문제] 6.2절의 `make_clip_grad_hook()`을 `MiniVGGNet`(배치 정규화 없음)의 모든 파라미터에 등록하고 학습해 보자. 기준값을 1.0으로 두었을 때와 훨씬 작은 값으로 두었을 때가 어떻게 다른지 관찰하고, 그 결과를 [표 2]의 기울기 노름과 함께 해석해 보자.

**7.** 5.6절의 [코드 10]으로 얻은 기울기가 [코드 9]의 `.grad`로 얻은 기울기와 같은 값인지 직접 확인해 보자. 그런 다음 `model.zero_grad()`를 부르지 않고 `backward()`를 **두 번** 실행하면 두 방법의 결과가 어떻게 달라지는지 관찰하고, 그 이유를 설명해 보자.

**8.** [도전 문제] 5.2절의 `StackedConvBN` 모델에서 **배치 정규화 계층만 모두 빼고**(합성곱과 ReLU만 남기고) 5.3절의 실험을 다시 해 보자. 거의 같은 두 입력의 출력 거리가 깊이에 따라 어떻게 변하는지 [표 8-6]과 비교하고, 그 차이가 8-3절의 주장과 어떻게 이어지는지 설명해 보자.
